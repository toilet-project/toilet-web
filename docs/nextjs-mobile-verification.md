# Next.js 모바일 회귀 검증

2026-09-05 · WBS #186 · preview만 반영, 운영 홈페이지 미전환

## 수정 사항

상세 카드에서 지역 목록을 열 때, 상세 URL에서 홈 URL로 돌아오는 후속 처리가 방금 연 목록까지 닫았다. 상세 선택 초기화와 지역 목록 닫기를 분리했다. 목록/마커 선택·닫기·지도 조작에서는 명시적으로 목록을 닫고, 상세 URL이 활성화되어 있을 때는 지역 목록을 겹쳐 표시하지 않는다.

지도 SDK, 기본 지도 위치, 거리 정렬, 목록 디자인, 로그인/API 계약은 변경하지 않았다. 린트 억제 표시를 추가하지 않았으며 검사 경고는 없다.

배포된 소스: `7a57a373f8e1fc316bd3ed42c03a436ed536a96b`.
[Linux 빌드 검증](https://github.com/toilet-project/toilet-web/actions/runs/33970449843)에서 lint, typecheck, 자동 테스트 39건, 두 가지 서버 HTML 검사, Workers 빌드 및 업로드 없는 배포 검사가 통과했다.

## 테스트 안전성 및 범위

`tests/mobile-preview-regression.cjs`는 공개 지도/상세/주소 조회를 실제로 사용하지만 인증 상태, OAuth 복귀, 동의, 내 제보, 제보 제출, 로그아웃은 브라우저 내부 응답으로 대체한다. 모든 미지정 쓰기를 차단하고 실패로 처리한다. 합성 검증의 Cloudflare 성능 통계도 전송하지 않는다. 실제 소셜 제공자 로그인·가입·제보 저장이 완료됐다는 의미가 아니다.

로컬 개발 서버에서도 기본 시나리오가 통과했다. HTTP 로컬 주소의 위치 기능은 테스트 브라우저에만 보안 컨텍스트를 모의했으며, 최종 preview 검증에서는 실제 HTTPS를 사용했다. 개발 도구가 버튼을 덮는 현상이 있었던 추가 시나리오는 배포용 preview에서 다시 통과했다.

재실행은 Playwright가 설치된 환경에서 `node tests/mobile-preview-regression.cjs`를 사용한다. 필요한 경우 `PLAYWRIGHT_MODULE_PATH`로 설치된 Playwright 경로를 지정한다. 기본 대상은 preview이며 테스트 전용 로컬 주소만 추가로 허용한다.

## 배포 후 공통 확인

- root/robots/정상 상세 HTTP 200, 잘못된 ID 두 종류 HTTP 404.
- 상세 캐시 MISS → HIT, 화장실 포함 metadata 및 preview noindex 유지.
- 재배포 후 기존 Spring 자동 캐시 연결도 확인용 대기열 이벤트로 재검증했다. 자동 전송/ACK와 새 빌드의 캐시 갱신을 확인했으며 원본 화장실 데이터는 변경하지 않았다.
- 기존 홈페이지·웹 main·요금제는 변경하지 않았다.

## 남은 확인 — 완료 처리하지 않음

- 실제 iPhone Safari: 키보드 열기/닫기 후 배율과 스크롤 복구, 주소창 높이 변화, 세로/가로 회전, 핀치 확대 및 확대 안내.
- 실제 소셜 로그인·신규 가입 동의 후 제보 복귀. 자동 테스트는 모의 응답이다.
- 알림의 실제 읽음 상태 저장, 모든 접근성/스크린리더 조합, 대규모 부하/Workers CPU 한도는 이번 검증으로 완료했다고 보지 않는다.
- 최종 운영 홈페이지 전환 승인.

따라서 WBS 전체는 진행 중으로 유지한다.

## 실기기 피드백 후 보완 — 가로 회전·키보드

사용자가 iPhone 가로 회전에서 데스크탑 목록으로 전환되는 현상과 긴 위치 제보 창에서 키보드를 닫은 뒤 헤더가 위로 밀리는 현상을 보고했다.

- 짧은 높이의 터치 화면은 가로에서도 모바일 구성을 유지한다. CSS와 지도 동작의 판별 조건을 함께 변경했다. 동일 해상도라도 마우스를 쓰는 데스크탑 구성은 유지한다.
- 제보 창을 여는 동안 배경 문서 스크롤을 잠그고, 닫을 때 기존 스타일과 스크롤 위치를 복구한다.
- 뒤로가기·제목·닫기를 별도 상단 영역으로 분리하고 제보 내용만 스크롤한다.
- VisualViewport 높이/상단 오프셋 변화에 맞춰 창을 조정하고 키보드 닫힘 후 문서 오프셋을 복구한다. 사용자 핀치 확대는 강제로 되돌리거나 차단하지 않는다.
- 제보 지도 크기가 바뀌면 지도 레이아웃을 다시 계산한다. 실제 위치/주소 저장 계약은 변경하지 않는다.

로컬 lint/typecheck 및 자동 테스트 41건이 통과했다. `tests/mobile-viewport-regression.cjs`에서 375×667, 390×844, 430×932의 세로↔가로 회전과 932×430 마우스 화면의 데스크탑 유지를 확인했다. 긴 내용 스크롤 중 상단 버튼 유지, 모의 키보드 닫힘 후 상단 위치 복구, 창 닫힘 후 배경 스타일/스크롤 복구, 확대 중 강제 원복하지 않음도 검증했다.

**키보드 이벤트는 합성 VisualViewport 입력이므로 실제 Safari 키보드 검증을 대체하지 않는다.** preview 배포 후 같은 실기기 동작을 다시 확인하고, 그 전에는 해당 항목을 완료로 처리하지 않는다. 실제 제보·계정 데이터 쓰기는 차단한 테스트다.

- 운영 홈페이지·main·백엔드·DB·요금제는 변경하지 않았다. 실제 iPhone 재확인 전까지 WBS는 진행 중이다.
