# 영어 장소 검색 · Cloudflare 1차 구성

## 현재 범위

- 한국어 검색은 기존 카카오맵 키워드 검색을 그대로 사용한다.
- 영어·일본어·중국어 화면은 같은 검색창에서 Cloudflare Worker와 검색 전용 D1을 사용한다. 영어 이름은 모든 화면에서 검색할 수 있고, 일본어·중국어 화면은 출처가 있는 해당 언어의 이름·별칭도 검색한다.
- 영어 지도는 네이버 지도의 영문 레이블을 사용한다. 한국어 지도와 검색은 현재 카카오 기본값을 유지한다.
- 지도 공급자와 검색 공급자는 독립 설정이다. 현재 UI에서 네이버 지도를 직접 선택해 `한국어 + 네이버 지도 + 카카오 검색` 조합으로 이용해도 검색 구현은 바뀌지 않는다. 직접 선택한 지도는 언어 변경 후에도 우선한다.
- Elasticsearch는 도입하지 않았다. 장소 데이터와 검토 상태를 먼저 정리해 두고, 검색량과 품질 요구가 커질 때 D1을 원본으로 별도 색인을 만들 수 있게 했다.
- 운영 도메인에는 아직 활성화하지 않는다. 운영 검색 D1은 프리뷰와 별도로 만들었지만 웹 Worker에는 연결하지 않았다.

## 데이터 상태

검토한 2,000건을 검색 전용 D1의 두 출처 묶음으로 나눠 보관한다. 좌표·주소 교차검토 결과를 검색 시드에 반영했다. 아래 건수는 새 시드의 검증 결과이며 운영 D1 반영을 뜻하지 않는다.

| 상태 | 건수 | 영어 검색 노출 |
|---|---:|---|
| 원본 검토상 시험 검색 가능 | 1,923 | 공식 역별 좌표로 보정한 20건을 포함해 프리뷰 노출 |
| 추가 검토 | 66 | 미노출 |
| 장소 아님 | 11 | 미노출 |

원본 시드의 2,000건은 모두 `productionApproved=false`다. 보류된 66건과 제외된 11건은 색인하지 않는다. 자세한 좌표 판단과 보류 이유는 각 행의 감사 정보에 남긴다.

2026-09-21에 프리뷰 후보 1,923건의 명백한 좌표 이상만 간이 점검했다. 좌표 누락·한국을 포함하는 대략적 범위 이탈·서로 다른 역의 동일 좌표는 0건이었고, 좌표가 있는 유효 교차자료 267건과 500m 넘게 어긋나는 후보도 없었다. 이는 출입구 위치나 모든 장소의 정확도를 보증하지 않는다. 현재 후보군의 건별 수동 전수검수와 자동번역 503개 전수검수는 중단하고, 후보군 재구축 시 별도로 다시 판단한다.

2026-09-22에 사용자가 **현재 검색 가능한 1,923건**을 첫 운영 검색 후보로 선택했다. 별도 승인 기록은 정확한 프리뷰 입력 SQL의 해시·시드 해시·승인/보류 건수를 고정한다. 운영용 SQL 생성 시에만 이 1,923건을 `search_scope=production`, `production_approved=1`로 표시하고, 원본 시드와 프리뷰 DB는 변경하지 않는다. 이는 검색 후보 데이터 선택이며 웹 서비스 연결·기능 활성화·운영 배포 승인은 아니다. 검색 좌표는 지도 중심으로만 사용하며 출입구 위치로 안내하지 않는다.

추가 품질 검사에서 역 정보 웹페이지의 공통 지도 중심을 서로 다른 역 20곳의 좌표로 잘못 취급한 수집·매핑 오류를 발견했다. 원래 역 좌표와 최대 약 18km 차이가 나서 한때 프리뷰 검색에서 제외했다. 이후 [철도 데이터 포털의 인천교통공사 역위치 파일](https://data.kric.go.kr/rips/M_01_01/detail.do?id=214)(2026-02-13 수정)의 역별 위도·경도를 원래 후보 좌표와 대조해 20곳을 각각 보정했다. 파일의 예전 이름 `서구청`은 [인천교통공사 현행 역 페이지](https://www.ictr.or.kr/main/subway/subwayStation.do?line_no=2&station_no=210)의 `서해구청역`과 연결했다. 원본 시드는 바꾸지 않고 파일 해시·행 번호·기존 잘못된 좌표를 감사 정보에 남겼다. 현재 프리뷰 검색 후보는 **1,923건**이다. 운영 승인은 여전히 별개다.

공공데이터도 일괄 신뢰하지 않는다. 비교용 2024년 인천 2호선 파일에는 `가정` 한 역의 좌표가 노선 범위를 크게 벗어난 값이 있어, 최신 파일과 원래 후보 좌표를 함께 확인했다. 보정 설정은 각 역의 원래 후보에서 250m 넘게 벗어난 좌표를 거부한다.

추가 중복 좌표 점검에서 부산 4호선 **명장역과 서동역이 같은 위치로 검색되는 오류**를 발견했다. [부산교통공사 공식 역사정보 파일](https://www.data.go.kr/data/15043686/fileData.do)의 역코드 406·407, 파일 107·108행에서 각각의 좌표를 확인해 프리뷰에 보정했다. 원본 서동역 좌표가 명장역과 약 1km 떨어진 실제 서동역 위치 대신 명장역에 찍혀 있었다. 파일은 2021-02-26 기준이며 출입구 위치를 나타내지는 않는다. 파일 해시·행·원래 좌표를 감사 정보에 보존했고, 검색 가능 건수 1,923건과 운영 비활성화 상태는 그대로다.

## 저장 구조

- `places`: 한·영 이름, 분류, 검토 상태, 검색 범위, 대표 좌표, 출처와 전체 감사 정보를 보관한다.
- `place_aliases`: 한·영 별칭을 분리해 보관한다.
- `place_localizations`: Wikidata의 일본어·중국어 지역별 이름·별칭과 원본 언어·개정 번호를 보관한다. 원본 표기가 없는 536개 언어별 이름을 영어에서 자동번역했고, 표본 검사에서 문제가 확인된 33개는 영어 이름을 유지한다. 원본 표기는 덮어쓰지 않는다. 자동번역 값은 프리뷰 시험용이며 운영 승인 상태가 아니다.
- 원본 표기와 다르지만 공식 자료에서 확인한 영어 별칭은 별도 검토 파일로 관리한다. 현재 `Myeongdong Station`은 [서울시 공식 표기](https://english.seoul.go.kr/real-time-foreign-language-system-begins-pilot-operations-at-myeongdong-station/)에 근거한 명동역 검색 별칭이다. 기존 장소 좌표나 공식 명칭은 바꾸지 않는다.
- `place_coordinate_candidates`: 복수 좌표 후보와 근거를 보존한다. 대표 좌표를 임의로 평균 내지 않는다.
- `place_search_fts`: 검색이 허용된 1,923건의 영어 색인이다. `place_search_localized_fts`는 같은 장소에 일본어·중국어 네 지역별 행을 만들고 영어 이름을 대체 검색어로 포함한다. 원본 보류·제외 77건은 검색 색인에 넣지 않는다.
- 모든 장소에는 내부 대분류와 함께 검색 결과에 표시할 한글·영문 세부 카테고리가 있다. 예: 공항/Airport, 역/Station, 공원/Park, 박물관/Museum, 대학교/University.
- 기존 Next.js 캐시 태그 D1과 검색 D1은 서로 분리한다.

원본 자료는 Wikidata와 geoBoundaries를 사용한 2026-09-20 검토본이다. 상세 출처와 라이선스는 시드 파일 메타데이터 및 검토 결과 문서에 함께 보존한다.

## 요청 흐름

1. 사용자가 한국어 화면에서 입력하면 기존 카카오 검색을 호출한다.
2. 사용자가 영어·일본어·중국어 화면에서 두 글자 이상 입력하면 300ms 입력 대기 후 `/api/place-search`로 작은 POST 요청을 보낸다. 화면 언어를 요청에 명시한다.
3. Worker는 해당 언어의 D1 FTS5 행에서 최대 10건을 찾는다. 일본어·중국어의 모음/발음부호는 검색 정규화 중 버리지 않는다.
4. 선택 결과의 대표 좌표로 해당 언어 화면의 네이버 지도 중심을 이동한다. 같은 화장실 조회 API와 마커·상세카드 로직을 사용하며 시설 원본은 바꾸지 않는다.

Wikidata에서 장소 ID별 일본어·중국어 이름과 별칭을 조회했다. 원본 검토상 프리뷰 대상 1,923건 중 일본어 1,840건, 중국 간체 1,775건, 대만 번체 1,773건, 홍콩 번체 1,768건에 해당 문자 이름이 있었다. 중국어는 지역별 원본을 우선하고, 동일 문자체계의 공통 표기를 보완에 사용한다. 다른 중국어 지역의 이름으로 대체하지 않는다.

남은 536개 언어별 이름은 영어에서 Google Cloud Translation Basic으로 번역했다. 홍콩 번체는 대만 번체 모델 결과를 보충용으로만 쓰고 홍콩 고유 표기로 취급하지 않는다. 번역되지 않은 고유명사 4개와, 박물관·공원·사찰 이름으로 잘못 번역된 29개는 영어 이름을 표시·검색한다. 따라서 자동번역 이름 503개가 후보에 남아 있다. 전체 언어 감수 완료로 표시하지 않으며, 알려진 33개 오류는 계속 차단한다.

이 이름은 검색 후보 표시값일 뿐 시설 원본이나 좌표를 바꾸지 않는다. 검색 결과의 지역·세부 카테고리 표시는 아직 영어다.

서해구청역은 Wikidata의 일본어·중국어 후보에 옛 이름이 남아 있었다. [운영기관의 현행 역 페이지](https://www.ictr.or.kr/main/subway/subwayStation.do?line_no=2&station_no=210)에 있는 일본어·중국어 역명을 기준으로 이 역의 후보 이름만 교정하고, 검색 편의를 위해 `駅`·`站`이 붙은 표기와 없는 표기를 함께 받는다. 원본 번역 파일은 보존하며 다른 역 이름에는 일괄 적용하지 않는다.

번역 보충은 `node scripts/fetch-google-place-fallbacks.mjs`로 대상·문자 수를 먼저 확인하고, Cloud Translation Basic 전용 API 키가 준비됐을 때만 환경변수 `GOOGLE_CLOUD_TRANSLATION_API_KEY`를 사용해 `--execute`로 생성한다. 키를 명령행·파일·로그에 기록하지 않는다. 요청 상한은 1만 원문자이며, 자동번역 결과에는 제공자·원문 언어·대상 언어·검토 필요 표시를 남겼다. 이번 후보에는 승인 기록에 고정된 503개가 포함되지만, 후보군을 다시 만들 때 감수·교체할 수 있다.

검색어는 DB에 저장하거나 분석 이벤트에 포함하지 않는다. POST 본문으로만 전달하고 응답도 `no-store`로 처리한다. 현재 분석 이벤트에는 검색어 대신 주소형/장소형 구분과 결과 건수 구간만 남는다.

## 캐시와 확장

- 새 프리뷰 검색 색인은 좌표를 보정한 인천 역 20곳과 부산 역 2곳을 포함해 1,923건이며, D1 FTS 조회 결과를 CDN이나 브라우저에 저장하지 않는다.
- 자동완성 결과는 최대 10건만 전송하므로 전체 장소 파일을 휴대전화에 내려받지 않는다.
- 데이터 변경은 검토 상태와 `search_scope`를 먼저 갱신한 뒤 FTS 행을 재생성한다.
- Elasticsearch를 도입할 때는 D1의 승인된 행만 읽어 새 색인을 만들고, 전환 기간에는 D1 검색을 안전한 대체 경로로 유지한다.

## 배포 경계

- 프리뷰: `PLACE_SEARCH_ENABLED=true`, `PLACE_SEARCH_SCOPE=preview`, 검색 전용 D1 연결.
- 프리뷰 지도: `NAVER_MAP_ENABLED=true`; 공개 브라우저 Client ID는 Worker 비밀값으로 주입하고 `/api/map-provider-config`에서 `no-store`로 전달한다. REST Secret은 사용하지 않는다.
- 운영 후보: `PLACE_SEARCH_ENABLED=false`, 검색 D1 연결 없음. 별도 `geupddong-place-search-production` DB는 APAC에 생성했으나 아직 빈 상태이며 Worker에 바인딩하지 않았다.
- 운영 후보 지도: `NAVER_MAP_ENABLED=false`; 별도 운영 승인 전에는 네이버 설정을 반환하지 않는다.
- 검색 API는 운영 범위가 명시돼 있고 해당 행의 `production_approved=1`일 때에만 운영 결과를 반환한다. 프리뷰 후보나 잘못된 범위 설정은 운영 승인으로 간주하지 않는다.
- 운영 활성화에는 별도 DB에 승인된 1,923건 적재·건수 검증, 네이버 지도 운영 도메인·이용량 제한 확인, 한국어 기존 검색과 다국어 검색의 실제 기기 회귀 확인이 필요하다. 이번 좌표 간이 점검과 후보 선택은 그 자체로 운영 배포 승인이 아니다.
