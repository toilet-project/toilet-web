# 영어 장소 검색 · Cloudflare 1차 구성

## 현재 범위

- 한국어 검색은 기존 카카오맵 키워드 검색을 그대로 사용한다.
- 영어·일본어·중국어 화면은 같은 검색창에서 Cloudflare Worker와 검색 전용 D1을 사용한다. 영어 이름은 모든 화면에서 검색할 수 있고, 일본어·중국어 화면은 출처가 있는 해당 언어의 이름·별칭도 검색한다.
- 영어 지도는 네이버 지도의 영문 레이블을 사용한다. 한국어 지도와 검색은 현재 카카오 기본값을 유지한다.
- 지도 공급자와 검색 공급자는 독립 설정이다. 현재 UI에서 네이버 지도를 직접 선택해 `한국어 + 네이버 지도 + 카카오 검색` 조합으로 이용해도 검색 구현은 바뀌지 않는다. 직접 선택한 지도는 언어 변경 후에도 우선한다.
- Elasticsearch는 도입하지 않았다. 장소 데이터와 검토 상태를 먼저 정리해 두고, 검색량과 품질 요구가 커질 때 D1을 원본으로 별도 색인을 만들 수 있게 했다.
- 운영 도메인에는 아직 활성화하지 않는다. 검색 전용 D1과 API는 프리뷰 범위로만 구성한다.

## 데이터 상태

검토한 2,000건을 검색 전용 D1의 두 출처 묶음으로 나눠 보관한다. 좌표·주소 교차검토 결과를 검색 시드에 반영했다. 아래 건수는 새 시드의 검증 결과이며 운영 D1 반영을 뜻하지 않는다.

| 상태 | 건수 | 영어 검색 노출 |
|---|---:|---|
| 시험 검색 가능 | 1,923 | 프리뷰에서만 노출 |
| 추가 검토 | 66 | 미노출 |
| 장소 아님 | 11 | 미노출 |

현재 2,000건 모두 `productionApproved=false`다. 따라서 프리뷰 검색 가능한 1,923건도 운영 승인이나 모든 좌표의 공식 측량 검증을 뜻하지 않는다. 보류된 66건과 제외된 11건은 색인하지 않는다. 자세한 좌표 판단과 보류 이유는 각 행의 감사 정보에 남긴다.

## 저장 구조

- `places`: 한·영 이름, 분류, 검토 상태, 검색 범위, 대표 좌표, 출처와 전체 감사 정보를 보관한다.
- `place_aliases`: 한·영 별칭을 분리해 보관한다.
- `place_localizations`: Wikidata의 일본어·중국어 지역별 이름·별칭과 원본 언어·개정 번호를 보관한다. 원본 표기가 없는 경우에만 영어 이름에서 Google Cloud Translation으로 번역한 값을 별도 자료로 보충할 수 있게 구성했다. 자동번역 자료는 아직 생성·반영하지 않았으며, 현재 부족한 이름은 영어로 표시한다.
- 원본 표기와 다르지만 공식 자료에서 확인한 영어 별칭은 별도 검토 파일로 관리한다. 현재 `Myeongdong Station`은 [서울시 공식 표기](https://english.seoul.go.kr/real-time-foreign-language-system-begins-pilot-operations-at-myeongdong-station/)에 근거한 명동역 검색 별칭이다. 기존 장소 좌표나 공식 명칭은 바꾸지 않는다.
- `place_coordinate_candidates`: 복수 좌표 후보와 근거를 보존한다. 대표 좌표를 임의로 평균 내지 않는다.
- `place_search_fts`: 프리뷰 검색이 허용된 1,923건의 영어 색인이다. `place_search_localized_fts`는 같은 장소에 일본어·중국어 네 지역별 행을 만들고 영어 이름을 대체 검색어로 포함한다. 보류·제외 77건은 어느 검색 색인에도 넣지 않는다.
- 모든 장소에는 내부 대분류와 함께 검색 결과에 표시할 한글·영문 세부 카테고리가 있다. 예: 공항/Airport, 역/Station, 공원/Park, 박물관/Museum, 대학교/University.
- 기존 Next.js 캐시 태그 D1과 검색 D1은 서로 분리한다.

원본 자료는 Wikidata와 geoBoundaries를 사용한 2026-09-20 검토본이다. 상세 출처와 라이선스는 시드 파일 메타데이터 및 검토 결과 문서에 함께 보존한다.

## 요청 흐름

1. 사용자가 한국어 화면에서 입력하면 기존 카카오 검색을 호출한다.
2. 사용자가 영어·일본어·중국어 화면에서 두 글자 이상 입력하면 300ms 입력 대기 후 `/api/place-search`로 작은 POST 요청을 보낸다. 화면 언어를 요청에 명시한다.
3. Worker는 해당 언어의 D1 FTS5 행에서 최대 10건을 찾는다. 일본어·중국어의 모음/발음부호는 검색 정규화 중 버리지 않는다.
4. 선택 결과의 대표 좌표로 해당 언어 화면의 네이버 지도 중심을 이동한다. 같은 화장실 조회 API와 마커·상세카드 로직을 사용하며 시설 원본은 바꾸지 않는다.

Wikidata의 `wbgetentities`에서 정확한 장소 ID와 언어별 이름·별칭을 가져왔다. 프리뷰 후보 1,923건 가운데 일본어 1,840건, 중국 간체 1,775건, 대만 번체 1,773건, 홍콩 번체 1,768건에 해당 언어 문자로 된 이름이 있다. 중국어는 지역별 직접 표기를 우선하고, 없을 때 같은 문자체계의 `zh-hans`/`zh-hant` 표기 및 공통 `zh` 표기의 문자체계 변환을 사용한다. 다른 중국어 지역 표기로 교차 대체하지 않는다. 아직 부족한 이름은 일본어 83건, 중국 간체 148건, 대만 번체 150건, 홍콩 번체 155건이다. 영어 원문 기준 Google Cloud Translation Basic 번역을 별도 보충 자료로 생성해 원본 표기를 덮어쓰지 않을 수 있게 했다. 홍콩 번체의 기본 NMT 모델은 대만 번체이므로 이를 보충용으로만 사용하고 홍콩 고유 표기로 취급하지 않는다. 번역 API 인증 및 결과 점검 전에는 영어 이름·검색어를 유지한다. 이름은 검색 후보 표시값이며, 시설 원본과 좌표를 변경하지 않는다. 검색 결과의 지역·세부 카테고리 표시는 아직 영어다.

번역 보충은 `node scripts/fetch-google-place-fallbacks.mjs`로 대상·문자 수를 먼저 확인하고, Cloud Translation Basic 전용 API 키가 준비됐을 때만 환경변수 `GOOGLE_CLOUD_TRANSLATION_API_KEY`를 사용해 `--execute`로 생성한다. 키를 명령행·파일·로그에 기록하지 않는다. 요청 상한은 1만 원문자이며, 자동번역 결과에는 제공자·원문 언어·대상 언어·검토 필요 표시를 남긴다. 생성된 파일은 프리뷰 검색에만 사용하고 운영에는 별도 품질 검토 후 반영한다.

검색어는 DB에 저장하거나 분석 이벤트에 포함하지 않는다. POST 본문으로만 전달하고 응답도 `no-store`로 처리한다. 현재 분석 이벤트에는 검색어 대신 주소형/장소형 구분과 결과 건수 구간만 남는다.

## 캐시와 확장

- 새 프리뷰 검색 색인은 1,923건이며, D1 FTS 조회 결과를 CDN이나 브라우저에 저장하지 않는다.
- 자동완성 결과는 최대 10건만 전송하므로 전체 장소 파일을 휴대전화에 내려받지 않는다.
- 데이터 변경은 검토 상태와 `search_scope`를 먼저 갱신한 뒤 FTS 행을 재생성한다.
- Elasticsearch를 도입할 때는 D1의 승인된 행만 읽어 새 색인을 만들고, 전환 기간에는 D1 검색을 안전한 대체 경로로 유지한다.

## 배포 경계

- 프리뷰: `PLACE_SEARCH_ENABLED=true`, `PLACE_SEARCH_SCOPE=preview`, 검색 전용 D1 연결.
- 프리뷰 지도: `NAVER_MAP_ENABLED=true`; 공개 브라우저 Client ID는 Worker 비밀값으로 주입하고 `/api/map-provider-config`에서 `no-store`로 전달한다. REST Secret은 사용하지 않는다.
- 운영 후보: `PLACE_SEARCH_ENABLED=false`, 검색 D1 연결 없음.
- 운영 후보 지도: `NAVER_MAP_ENABLED=false`; 별도 운영 승인 전에는 네이버 설정을 반환하지 않는다.
- 운영 활성화에는 공식 위치·표기 검토, 별도 운영 D1, 실제 아이폰 검색 품질과 비용 확인이 필요하다.
