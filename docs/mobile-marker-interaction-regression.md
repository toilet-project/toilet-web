# 모바일 마커 재선택 회귀 보완 (2026-09-06)

## 보고와 확인 범위

- 사용자 보고: iPhone Chrome, preview, 월드컵경기장역 재선택 시 카드 확대·거리 표시 소실·기준점 이동처럼 보이는 현상. 기존 제공 영상과 동일한 증상.
- 데스크톱 브라우저의 모바일 크기 재현만으로 iOS 문제가 없다고 판단하지 않는다. 실제 iPhone 해결 여부는 사용자 재검증 전까지 미확정이다.
- 기존 프리뷰의 HTML/RSC 응답은 서로 구분되어 반환되고 동일한 배포 버전을 사용했다. 이것만으로 사용자 기기의 캐시 문제를 배제하거나 확정할 수는 없다.

## 코드에서 확인한 취약 경로와 보완

1. 재사용되는 상세 카드의 내부 스크롤을 선택 변경 때 초기화하지 않았다. 선택 ID 변경 및 접기/펼치기 버튼 클릭 시 맨 위로 복원한다.
2. 카드 전체에서 단순 Y 이동만으로 확대했다. 상단 손잡이에서 시작된 단일 터치의 수직 상향 이동만 허용하며, 취소·핀치·다른 손가락·가로 이동과 후속 합성 클릭을 구분한다.
3. 마커 차단이 pointerdown/click과 짧은 시간창에 의존했다. 모든 마커 경로에 touchstart/mousedown, Kakao preventMap, clickable 옵션을 적용한다. 컨트롤의 touch-action: manipulation으로 이중 탭 확대를 줄이되 페이지 핀치 확대는 금지하지 않는다.
4. GPS 단발 요청이 늦게 완료되면 검색 기준점을 덮어쓸 수 있었다. 요청 세대 번호와 지도 인스턴스를 확인하여 새 기준점·후속 요청·지도 정리 이후의 결과/오류는 무시한다.
5. 브라우저 검증에서 화면 크기 변경 뒤 지도 중심이 옆으로 이동하는 것을 관찰했다. ResizeObserver의 SDK relayout 전후로 같은 중심 좌표를 복원한다. 이 과정에서는 거리 기준점과 확대 레벨을 변경하지 않는다.

이 경로들은 코드상 보완 대상이며, 영상의 복합 증상 전체에 대한 단일 원인으로 확정한 것은 아니다.

## 검증

- lint, TypeScript, 단위/소스 회귀 테스트 85건 통과.
- 새 테스트: 오래된 GPS 응답, 손잡이 정상 스와이프/합성 클릭, 취소/다중 터치/방향/식별자, 스크롤 초기화 연결, 세 마커 경로의 이벤트 차단.
- 실제 iPhone Chrome의 터치·확대 동작은 별도 최종 확인 필요. 캐시 삭제를 해결책이나 검증 전제로 요구하지 않는다.
