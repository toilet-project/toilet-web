# 계정 복구 인수 중 발견한 내 제보 조회 인증 처리

## 관찰과 판단

- 복구된 계정은 정상 상태이고 기존 제보 연결도 유지됐으나, 내 제보 조회에서 로그인 필요 안내가 표시됐다.
- 새로고침 후에는 목록과 상세가 정상 표시됐다. 제보 데이터 유실은 확인되지 않았다.
- 기존 소스는 로그인 상태 조회만 401 응답에 대해 refresh를 시도하고, 내 제보 조회는 401을 그대로 오류로 표시했다.
- 이 처리 차이는 관찰된 현상과 일치한다. 실제 토큰 원문·정확한 만료 시각은 수집하지 않았으므로 토큰 만료 원인을 직접 입증했다고 표현하지 않는다.

## 변경 범위

- 현재 회원 조회와 내 제보 조회에 GET 전용 세션 갱신 처리를 공유한다.
- 첫 401에만 세션 갱신을 시도하고 원래 GET을 최대 한 번 재조회한다.
- 동시 조회는 진행 중인 갱신을 공유하며, 성공한 갱신 전의 늦은 401 때문에 추가 갱신하지 않는다.
- 갱신 실패, 두 번째 401, 그 외 상태 코드는 반복하지 않는다. 네트워크 예외는 호출자에게 전달한다.
- 회원별 조회에는 credentials=include와 cache=no-store를 사용한다. 응답 데이터·토큰을 별도로 저장하지 않는다.
- 제보 제출·프로필 변경·탈퇴·복구 등 변경 요청은 자동 재전송하지 않는다.
- DB·운영 설정·회원 데이터·관리자 권한은 변경하지 않는다.

## 검증

- 추가 단위 테스트 10건: 정상 조회, 만료 후 갱신, 반복 401 차단, 갱신 실패, 비인증 오류, 동시 갱신, 늦은 401, 갱신/조회 네트워크 실패, 적용 범위 제한.
- 전체 자동 테스트 113건 통과.
- 기존 계정의 내 제보 목록과 상세는 새로고침 후 실제 화면에서 확인했다. 이는 수정 코드의 운영 검증이 아니다.
- 새 코드의 preview/운영 인수, 실제 모바일, 탈퇴 상태 작성자 표시, 보관 철회와 정기 배치는 별도다.

공개 문서에는 계정 식별정보·닉네임·이메일·제보 원문·해시·서버 접속정보·비밀값을 포함하지 않는다.
