# 초기 지도 표시 병목과 3차 개선

## 목적과 상태

지도 코드 준비, 외부 SDK, 데이터 응답, 마커 부착, React 결과 반영을 나누어 초기 대기를 줄인다. [관련 PR](https://github.com/toilet-project/toilet-web/pull/378)에서 검증 상태를 갱신하며, [실데이터 프리뷰](https://preview.geupddong.com/)를 검수한다. 운영 반영은 별도 승인 후 진행한다.

## 확인한 흐름과 변경

- 코드가 준비된 뒤에도 로딩 화면의 Suspense 재시도가 지도 마운트를 지연시킬 수 있었다. 지도는 원래 경로 등록 이후에만 클라이언트에서 마운트하므로, 준비된 모듈을 직접 마운트하도록 바꿨다. 모듈의 중복 다운로드 방지·실패 재시도·언마운트 이후 갱신 차단·기존 오류 화면은 유지한다.
- 홈이 상세 카드와 리뷰의 초기 의존성을 함께 참조했다. 홈 전용 경로 등록 컴포넌트로 분리하고, 상세 페이지의 서버 렌더링은 유지한다.
- 첫 지도 조회와 지역별 페이지의 자동 미리 읽기가 겹쳤다. 자동 미리 읽기는 첫 지도 결과 반영 후 두 프레임이 지난 뒤 허용하며, 사용자의 마우스·키보드 포커스·터치에는 즉시 허용한다.
- 단일 구역 캐시가 전역 변경번호와 구역 본문을 순서대로 읽었다. 두 읽기를 동시에 시작하고 마지막 변경번호 검증을 유지한다. 따뜻한 캐시와 원본 갱신 모두 R2 읽기 횟수를 늘리지 않는다.
- 목록 정렬과 표시에서 같은 거리를 반복 계산했다. 구역별 거리 한 번을 정렬·표시에 재사용하고, 목록과 기준 좌표가 같으면 정렬을 재사용한다. 이 계산은 일반적인 목록 크기에서 주요 지연 원인으로 해석하지 않는다.

## 계측 방법과 제한

프리뷰에서 `?map-timing=1`로 명시한 검사 페이지에만 숫자 형태의 구간 기록을 남긴다. 기록은 해당 페이지의 숨겨진 DOM 출력에만 있으며 서버나 분석 서비스에 전송하지 않는다. 운영 호스트와 일반 프리뷰 방문에서는 계측을 실행하지 않는다. 계정·좋아요·위치·본문·헤더·리소스 URL은 기록하지 않는다.

계측은 HTML 응답, 모듈 준비, SDK 준비, 지도 생성, 데이터 응답, 마커 준비·부착, 결과 DOM 반영을 구분한다. 서로 겹치는 SDK 준비와 코드 다운로드 시간을 단순 합산하지 않는다. 브라우저 캐시와 접속 지점 변화, 자동 조작, 탭의 가시성 영향을 기록한다. DOM에 첫 결과가 반영된 시점은 지도 타일이 모두 그려진 시점과 구분하며, 캐시가 유지된 새 탭 측정을 캐시 없는 첫 방문으로 해석하지 않는다.

단일 구역의 통신 비교는 같은 공개 구역에서 워밍업과 측정을 구분하고, 상태·응답 집합·원본 조회 유무·연결 준비·첫 바이트 대기·다운로드를 함께 확인한다. 구간별 측정값과 개별 표본은 공개 본문에 나열하지 않고 별도 진단 기록으로 관리한다.

## 데이터·권한 경계

2차의 공개 원본 재사용 기간과 계정별 자료 경계는 유지한다. 단일 구역 병렬 읽기도 변경·삭제 무효화와 갱신 소유권 검사를 유지하며, 이전 자료를 되살리지 않아야 한다. 새 원본의 프리뷰 서버 유효 기간과 기존 일반 조회의 갱신 정책은 [2차 비교 기준](./map-performance-comparison.md)을 따른다.

실제 모바일 기기와 캐시 없는 첫 방문의 지연, 모든 환경에서의 첫 화면 1초 미만 보장은 별도 검증 대상이다.
