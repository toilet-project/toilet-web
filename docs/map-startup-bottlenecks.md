# 초기 지도 표시 병목과 첫 방문 개선

## 목적과 상태

지도 코드 준비, 외부 SDK, 데이터 응답, 마커 부착, React 결과 반영을 나누어 초기 대기를 줄인다. [관련 PR](https://github.com/toilet-project/toilet-web/pull/378)에서 검증 상태를 갱신하며, [실데이터 프리뷰](https://preview.geupddong.com/)를 검수한다. 운영 반영은 별도 승인 후 진행한다.

## 확인한 흐름과 변경

- 코드가 준비된 뒤에도 로딩 화면의 Suspense 재시도가 지도 마운트를 지연시킬 수 있었다. 지도는 원래 경로 등록 이후에만 클라이언트에서 마운트하므로, 준비된 모듈을 직접 마운트하도록 바꿨다. 모듈의 중복 다운로드 방지·실패 재시도·언마운트 이후 갱신 차단·기존 오류 화면은 유지한다.
- 홈이 상세 카드와 리뷰의 초기 의존성을 함께 참조했다. 홈 전용 경로 등록 컴포넌트로 분리하고, 상세 페이지의 서버 렌더링은 유지한다.
- 첫 지도 조회와 지역별 페이지의 자동 미리 읽기가 겹쳤다. 자동 미리 읽기는 첫 지도 결과 반영 후 두 프레임이 지난 뒤 허용하며, 사용자의 마우스·키보드 포커스·터치에는 즉시 허용한다.
- 단일 구역 캐시가 전역 변경번호와 구역 본문을 순서대로 읽었다. 두 읽기를 동시에 시작하고 마지막 변경번호 검증을 유지한다. 따뜻한 캐시와 원본 갱신 모두 R2 읽기 횟수를 늘리지 않는다.
- 목록 정렬과 표시에서 같은 거리를 반복 계산했다. 구역별 거리 한 번을 정렬·표시에 재사용하고, 목록과 기준 좌표가 같으면 정렬을 재사용한다. 이 계산은 일반적인 목록 크기에서 주요 지연 원인으로 해석하지 않는다.
- 첫 로그인 상태 확인을 계정 변경과 똑같이 처리해, 이미 시작한 공개 지도 조회까지 취소하는 경로가 있었다. 첫 인증 확정 한 번에 한해 완전히 공개된 선택의 조회를 보존한다. 저장된 내 화장실 선택·권한 대기·개인 ID 조건은 제외하며, 이후 로그인·로그아웃·계정 전환은 기존 초기화를 유지한다. 탭 복귀·제보·다시 시도의 갱신은 변경하지 않는다.
- 지도 App이 공개 후기·후기 작성·내 후기·약관 동의·계정 복구 화면을 동기로 참조했다. 작은 아이콘과 로딩 표시만 분리해 유지하고, 실제 패널은 열 때 읽도록 바꾼다. 공개 후기 서버 렌더링과 전역 스타일 순서는 유지하며, 불러오기 실패 시 닫기·재시도 경로를 제공한다.
- 홈 HTML에 실제 지도 제공자와 공개 API의 연결 준비 힌트를 넣어, 클라이언트 코드 준비와 연결 수립을 겹칠 수 있게 한다. 데이터·위치 조회를 미리 실행하지 않는다.
- 구역 조회 실패 뒤 일반 API도 실패하면 같은 일반 조회를 한 번 더 시도하는 경로를 제거한다. 정상 조회의 속도 절감으로 해석하지 않으며, 기존 대체 조회 조건과 취소 전파는 유지한다.

## 계측 방법과 제한

프리뷰에서 `?map-timing=1`로 명시한 검사 페이지에만 숫자 형태의 구간 기록을 남긴다. 기록은 해당 페이지의 숨겨진 DOM 출력에만 있으며 서버나 분석 서비스에 전송하지 않는다. 운영 호스트와 일반 프리뷰 방문에서는 계측을 실행하지 않는다. 계정·좋아요·위치·본문·헤더·리소스 URL은 기록하지 않는다.

계측은 HTML 응답, 모듈 준비, SDK 준비, 지도 생성, 데이터 응답, 마커 준비·부착, 결과 DOM 반영을 구분한다. 서로 겹치는 SDK 준비와 코드 다운로드 시간을 단순 합산하지 않는다. 브라우저 캐시와 접속 지점 변화, 자동 조작, 탭의 가시성 영향을 기록한다. DOM에 첫 결과가 반영된 시점은 지도 타일이 모두 그려진 시점과 구분하며, 캐시가 유지된 새 탭 측정을 캐시 없는 첫 방문으로 해석하지 않는다.

단일 구역의 통신 비교는 같은 공개 구역에서 워밍업과 측정을 구분하고, 상태·응답 집합·원본 조회 유무·연결 준비·첫 바이트 대기·다운로드를 함께 확인한다. 구간별 측정값과 개별 표본은 공개 본문에 나열하지 않고 별도 진단 기록으로 관리한다.

서버 구간은 프리뷰 홈의 `?map-server-timing=1` 진단 GET에만 숫자 `Server-Timing`을 반환해 확인한다. 요청별 환경을 감싸 OpenNext 응답 준비, R2 읽기·본문 해석, D1 태그 조회의 시간·횟수를 측정하며 원본 바인딩과 캐시 정책을 변경하지 않는다. 응답 반환 시점의 미완료 저장소 호출·백그라운드 작업 수를 함께 표시한다. 응답 헤더 이후의 스트리밍·백그라운드 완료를 기다리지 않으며, 상위 응답 준비 시간에 저장소 시간을 다시 더하지 않는다. 운영·일반 프리뷰·RSC·미리 읽기·재검증 요청은 이 서버 계측에서 제외한다.

배포된 Workers의 시계는 [I/O 뒤에만 진행한다](https://developers.cloudflare.com/workers/runtime-apis/performance/). 따라서 서버 구간은 I/O 경과 관측값이며 동기 처리의 CPU 시간을 정밀하게 구분할 수 없다. 본문 해석이 0으로 나와도 비용이 없다는 뜻은 아니다. 요청 전체 CPU·실행 수명은 검사 요청만 골라낸 Workers 추적으로 별도 확인하며, 백그라운드 작업까지 포함할 수 있는 실행 수명을 브라우저 첫 응답 시간과 동일시하지 않는다.

허가된 독립 브라우저는 매번 로그인·저장소·브라우저 캐시가 없는 컨텍스트와 같은 공개 장소 합성 위치를 사용한다. Navigation/CDP로 연결 준비·응답 대기·본문 수신과 초기 코드 통신을 구분한다. 원시 네트워크·실행 추적은 파일로 남기지 않고 고정 분류별 숫자만 보존한다. 메인 스레드 작업의 경과 시간은 순수 CPU 시간이나 React 전용 처리 시간으로 부르지 않으며, 중첩 이벤트는 합집합으로 집계한다. 같은 표본의 연속 구간만 합산하고 구간별 중앙값은 서로 더하지 않는다.

## 데이터·권한 경계

2차의 공개 원본 재사용 기간과 계정별 자료 경계는 유지한다. 단일 구역 병렬 읽기도 변경·삭제 무효화와 갱신 소유권 검사를 유지하며, 이전 자료를 되살리지 않아야 한다. 새 원본의 프리뷰 서버 유효 기간과 기존 일반 조회의 갱신 정책은 [2차 비교 기준](./map-performance-comparison.md)을 따른다.

독립 데스크톱 첫 방문 전후 각 5회 비교를 완료했으며 첫 결과와 위치 이동 후 안정된 결과를 구분했다. 서버 캐시·OS DNS까지 비어 있는 조건, 위치 권한 선택 시간, 실제 모바일 기기, 지도 타일의 완전한 표시와 모든 환경에서의 첫 화면 1초 미만 보장은 별도 검증 대상이다.
