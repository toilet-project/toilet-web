# 영어 UI 1차 지원 계획

승인일: 2026-09-19 · 개발 5주차(9/14~9/20) 착수. 전체 완료일은 검증 범위를 확인한 뒤 정한다.

## 목표와 경계

자동번역 서비스 없이 영어 사용자가 화장실 탐색, 로그인, 리뷰·제보, 내 페이지와 알림을 이용하도록 한다. 한국어 기능과 주소는 유지한다. Google Cloud Translation 연결·비용 발생, 관리자 영어화, 운영 배포는 이번 착수 범위에서 제외한다. 공개 프리뷰 게시 전 동시 작업을 대조하고 운영 배포는 별도 승인받는다.

## 승인한 헤더

- 모바일 홈의 삼선 메뉴·로그인 버튼 자리를 현재 언어 국기 버튼으로 교체한다.
- 버튼 아래 드롭다운: 대한민국 국기 + KOR, 미국 국기 + EN. 선택 항목 체크, 바깥 클릭·Escape·재클릭으로 닫기.
- 닫혔을 때 국기만 표시하되 접근성 이름은 현재 언어와 언어 선택 동작을 설명한다. 국기는 플랫폼 이모지 대신 동일한 SVG 자산을 쓴다.
- 시각적 크기는 작게, 터치 영역과 키보드 포커스는 충분히 확보한다.
- 데스크톱 기존 메뉴는 유지하고 언어 선택을 추가한다.
- 기존 메뉴에만 있는 링크는 내 페이지 등 대체 접근 경로를 확인한 뒤 제거한다. 로그인과 로그아웃 기능은 유지한다.

## 원문 유지 정책

리뷰·제보 본문, 관리자 자유 답변, 자유 형식 운영시간·시설 설명은 원문을 유지한다. 공식 영문이 없는 시설명·주소는 한국어를 유지한다. API 열거형이나 명확한 정형 값만 영어 라벨로 표시하며 원본 DB를 번역문으로 덮어쓰지 않는다. 일일 작성 제한·수정 기간·거리 제한 등 업무 규칙과 한국 기준 시간은 변경하지 않는다.

## 동시 작업 안전

관리자 상세 작업은 별도 관리자/API 저장소에 있지만 사용자 웹 Worker의 /admin-toilets-preview/ 배포 경로를 공유한다. 별도 사용자 웹 작업도 진행 중이다. 구현은 독립 worktree에서 하고 다른 브랜치의 파일·DB·배포 설정은 수정하지 않는다. App·공통 스타일·Worker·분석 경로는 통합 충돌 후보이므로 게시 직전 다시 비교한다. 현재 확인만으로 이후 변경까지 무충돌이라고 단정하지 않는다.

## 구현 순서

1. 안전한 문구/경로 기반과 언어 선택 컴포넌트부터 단위 검증한다.
2. 공유 지도 레이아웃을 유지하면서 실제 영어 경로와 헤더를 연결한다. 미완성 영어 화면으로 사용자를 보내는 버튼은 운영 노출하지 않는다.
3. 기능별 문구를 변환하고 원문 유지 영역을 분리한다.
4. 캐시 무효화·SEO·로그인 복귀를 검증한 뒤 프리뷰에서 인수한다.

추적 근거는 관련 PR·테스트 링크로 간결하게 남기며 구현, 프리뷰, 운영 완료를 구분한다.

## 현재 진행 상태 · 2026-09-19

WBS: [WEB #275](https://github.com/toilet-project/toilet-web/issues/275) · **진행 중 / 로컬 검증 / 운영 미반영**

### 구현·검증한 내용

- 국기 메뉴와 /en·영어 상세 경로를 연결했다. 언어 전환·앞뒤 이동 시 같은 지도와 선택 시설을 유지한다. 첫 HTML의 언어도 올바르다.
- 로그인 안내, 내 페이지 홈, 내 리뷰·제보·알림, 기간 필터·달력을 영어 문구에 연결했다.
- 리뷰 작성·수정·작성자 정보 제거, 제보 입력·접수 안내와 주요 오류를 영어로 제공한다. 입력 내용과 별점·거리·수정 가능 기간 규칙은 변경하지 않았다.
- 날짜는 영어로 표시하더라도 한국시간 기준을 유지한다. 시설명·주소·작성자 이름·리뷰와 제보 본문·관리자 답변은 원문이다.
- 알림의 승인·반려 제목은 유형에 따라 영어로 표시하고, 저장된 알림 본문은 원문임을 표시한다. 자유문구를 자동번역하거나 DB를 수정하지 않는다.
- 시설 변경 시 두 언어 페이지를 함께 무효화한다. 공개 시설 원본 캐시는 공유하며 로그인 복귀에는 허용된 로컬 경로만 짧게 보관한다.
- 최신 이용분석 [PR #274](https://github.com/toilet-project/toilet-web/pull/274)을 로컬에 통합했다. 분석 주소 분류 충돌을 해결하며 새 허용 목록과 분석 호출을 보존했다. 영어 상세에서도 시설 ID·쿼리를 추가 수집하지 않는다.

지도·목록·상세 카드·공개 리뷰·데스크톱 메뉴와 주요 지도/위치 오류도 영어로 연결했다. 언어 전환은 지도 마커의 문구만 바꾸며 지도·카메라를 재생성하지 않는다. 공개 리뷰는 삭제된 작성자만 Anonymous로 표시하고 실제 닉네임·본문은 원문을 보존한다. 계정·가입의 정책 영역에는 한국어 원문 안내를 표시했다.

### 검사 결과

**단위·회귀 262개, 타입 검사, 린트, 최적화 빌드 통과.** 개발 모드와 최적화 빌드에서 320px·390px 모바일, 1280px 데스크톱을 확인했다.

모바일에서는 로그인 안내 → 내 제보/달력 → 알림 → 리뷰 작성·수정·작성자 정보 제거 → 제보 접수 흐름을 검사했다. 달력과 리뷰 입력창을 화면으로 확인했고, 사용자 원문 보존도 확인했다. 기존 인증·기간·거리 규칙 검사는 유지했다.

API·계정·시설·위치·지도 SDK는 모두 로컬 합성 데이터다. 리뷰는 시험 브라우저 메모리에, 제보는 임시 로컬 서버에만 기록했다. 외부 브라우저 통신은 차단했다. 실제 카카오 지도·iPhone·소셜 로그인·리뷰 저장 API 통합 인수를 대신하지 않는다. 시험 서버와 브라우저는 종료했다.

### 남은 작업

1. 원문 유지 영역과 잔여 보조 화면의 최종 문구 대조.
2. 계정 관리·프로필 사진·가입 동의·탈퇴/복구와 정책 영문 검수.
3. 색인 범위·hreflang·사이트맵·prewarm/정리·캐시 격리 종합 점검.
4. 최신 관리자 프리뷰 변경 대조 → 프리뷰 게시 → 실제 지도·iPhone·로그인 인수.

영어 화면은 명시적으로 켠 프리뷰 빌드에서만 열리며 noindex다. 사용자가 프리뷰 게시까지 승인했다. 사용자 기능 브랜치와 관리자 정적 자산을 보존할 통합 프리뷰 브랜치를 구분해 검증·게시한다. 자동번역 연결·main 병합·운영 배포는 하지 않는다. 프리뷰 리뷰 입력은 기존 메모리 체험 방식이며 운영 DB 저장 검증이 아니다. 로그인·제보 등 기존 API 연결은 유지하므로 실계정 변경을 자동 시험하지 않는다.
