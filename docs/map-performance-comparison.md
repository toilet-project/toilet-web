# 지도 속도 2차 개선과 비교 기준

## 목적과 상태

현재 지도 범위에서 편의시설 조건을 연속으로 바꿀 때 서버 응답을 매번 기다리는 흐름을 줄인다. 기존 버전·1차 개선·2차 개선을 같은 실데이터 프리뷰에서 비교하며, 운영 반영은 별도 승인 후 진행한다.

## 변경 범위

1차 개선은 초기 코드 분리, 지도 SDK 병렬 준비, 같은 범위의 진행 중 요청 통합, 구역 간 캐시 변경번호 조회 공유다. 자세한 내용은 [1차 개선 문서](./map-startup-performance.md)를 따른다.

2차 개선은 개별 조건에 맞는 결과 대신, 현재 필요한 구역의 **완전한 공개 화장실 자료와 편의시설 속성**을 잠시 재사용하는 방식이다. 필터를 바꾸면 해당 자료를 화면에서 계산하고, 지도 이동 시 새로 필요한 구역만 요청한다. 최초의 일반 지도 조회에 별도 자료 다운로드를 추가하지 않는다.

- 부분 결과·속성 누락·지원하지 않는 필터 자료 형식은 완전한 구역으로 취급하지 않는다.
- 신규 구역 원본은 현재 공개 API의 완전한 편의시설 속성을 사용한다. 과거 프리뷰 스냅샷으로 걸러진 구역 캐시와 저장 공간을 분리하고, 수정·삭제 시 새 원본 캐시도 함께 무효화한다.
- 전국 확대 집계와 구역 수 제한을 넘는 범위는 기존 서버 집계 경로를 유지한다.
- 개인의 좋아요 ID와 필터 결과는 공개 구역 자료에 저장하지 않는다. 계정 변경·화면 정리 시 진행 중 작업과 화면 내 자료를 정리한다.
- 브라우저 재사용 유효 기간은 15초다. 공개 정보의 수정·삭제가 화면에 반영되기까지 이 재사용으로 최대 15초의 지연이 추가될 수 있다. 영구 저장소·공유 HTTP 응답 캐시로 확장하지 않는다.

## 속도 비교 방법

서버 응답과 사용자가 보는 필터 전환은 서로 다른 지표다. 두 수치를 합쳐 속도 개선율로 표현하지 않는다.

| 지표 | 측정 조건 | 해석 |
| --- | --- | --- |
| 지도·필터 서버 응답 | 동일 프리뷰 호스트, 공개 고정 범위·확대 수준·필터, 비로그인 요청. 조건별 워밍업을 분리한 뒤 20회 이상 측정 | 통신과 서버 대기를 포함한다. 중앙값·95백분위·1초 미만 비율·실패를 함께 본다 |
| 화면의 필터 전환 | 동일 기기·브라우저·지도 범위·표시 조건. 자료를 받은 직후와 유효 기간이 지난 뒤를 구분 | 조건 선택부터 해당 조건의 결과 표시까지 측정한다. 추가 지도 요청 유무도 확인한다 |
| 홈페이지 진입 | HTML부터 지도·마커 표시까지 측정. 외부 SDK·위치 권한·브라우저 캐시 조건을 명시 | HTTP 조회나 초기 코드 용량만으로 첫 화면 시간을 대신하지 않는다 |
| 결과 정확성 | 동일 범위·필터의 반환 화장실 집합을 비교 | 일부 항목이 빠져서 빨라진 결과를 개선으로 판단하지 않는다 |

기존 버전과 1차 빌드는 같은 Next.js·의존성·실데이터 프리뷰 기능 설정을 사용한다. 배포 순서, 접속 지점, 캐시 준비 상태의 차이를 기록하고 통제하지 못한 차이는 측정의 제한으로 남긴다. 실제 통신 수치와 개별 표본은 공개 문서에 옮기지 않고 승인된 운영 검증 기록에서 관리한다.

## 완료 기준

- [ ] 누락·중복·잘못된 필터 결과가 없는지 확인
- [ ] 좋아요·로그인 전환과 공개 자료의 경계 확인
- [ ] 자료 만료·실패·중단·수정/삭제 반영 시험
- [ ] 기존·1차·2차 서버 응답과 화면 전환을 구분해 비교
- [ ] 실데이터 프리뷰에서 검색·필터·상세·다국어·모바일 확인
- [ ] 운영 승인 및 반영

모든 첫 방문이나 모든 통신 환경에서 1초 미만을 보장하는 기준은 아니다. 우선 현재 범위의 자료가 준비된 뒤 반복하는 필터 전환을 1초 미만으로 줄이고, 처음 받는 구역과 전국 집계의 대기는 별도로 평가한다.
