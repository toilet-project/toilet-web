# 회원 성장 화면

## 목적과 운영 상태

- 운영 공통 헤더와 계정 사이드바 안에 프로필·성장 정보를 함께 제공한다.
- 기본 마이페이지, 프로필 수정, 성장 가이드 경로를 구현했다. 기존 사진 선택·크롭·삭제·공개 설정과 닉네임 API를 재사용한다.
- `NEXT_PUBLIC_GROWTH_ENABLED`는 기본 비활성이다. 비활성·서버 오류를 가짜 레벨이나 경험치로 대체하지 않는다.

운영 반영의 최신 상태와 남은 작업은 [회원 성장 운영 반영 WBS](https://github.com/toilet-project/docs/issues/121)에서 관리한다. 트래픽 전환, 최종 서버 검증, 실제 브라우저 확인의 완료 여부도 해당 WBS를 기준으로 한다.

## 데이터와 표시

- `/api/v1/growth/me`의 서버 요약만 회원 레벨·경험치·배지 보유 상태로 표시한다.
- 접속 보상 대상일 때만 `/api/v1/growth/check-in`을 호출한다. 동일 회원의 헤더·마이페이지 요청은 공유하며 서버가 지급 중복을 최종 통제한다.
- 리뷰 저장·수정·익명 전환 후 요약을 새로 확인한다. 로그아웃과 인증 만료 시 메모리 데이터를 비운다.
- 오류 시 재시도를 제공하고, 접속 보상만 실패한 경우 마지막으로 확인한 서버 경험치와 실패 안내를 함께 표시한다.
- `/growth/ranks`, `/growth/levels`는 승인된 휴지 원본과 안내 디자인을 사용한다. 모션 감소 설정에서는 정지 SVG로 표시한다.
- 지역·시군구 배지는 승인 자산의 코드·등급으로 연결한다. 비회원 계산기는 회원 기록과 분리된 0 XP 기준임을 명시한다.
- 한국어·영어·일본어·중국어 간체/번체 성장 안내를 제공한다.
- 개인별 데이터는 로컬 저장소에 저장하지 않는다. 프로필 설정 변경은 기존 운영 API로 전달한다.
- 공개 리뷰의 사진 자리는 서버가 제공하는 현재 `authorRank`의 24px 휴지 아이콘으로 표시한다. 익명·등급 미제공·성장 비활성 상태에는 기본 아이콘을 사용하며 프로필 사진 선로딩은 하지 않는다. 빨강 이상은 기존 GIF와 모션 감소용 SVG를 재사용한다.
- 상단 프로필 버튼은 사진·닉네임만 표시하고, 열린 드롭다운의 마이페이지 행에는 휴지 등급·레벨을 유지한다.
- 공개 리뷰는 재조회 시 현재 등급을 반환한다. 이미 읽은 목록에는 기존 30초 메모리 캐시가 적용되며 회원 식별자나 개인 경험치를 공개 응답에 추가하지 않는다.

## 모바일 마이페이지 검수

- 모바일 하단 내비게이션의 내 페이지에 휴지 등급·현재 레벨·다음 레벨까지 남은 경험치를 표시한다. 프로필과 성장 카드는 분리하고, 성장 카드 아래에는 작은 안내 링크를 둔다.
- 획득 배지는 닉네임 옆에 18px 아이콘으로 최대 3개를 표시한다. 자세한 수집 기록은 내 좋아요 바로 아래의 내 업적에서 확인한다.
- 기존 사진·닉네임 수정과 계정 메뉴, 성장 API의 상태 처리·접속 보상을 재사용한다.
- 사용자 검수는 실데이터에 연결된 [공식 프리뷰 내 페이지](https://preview.geupddong.com/?tab=account)에서 진행한다. 실제 계정 변경과 접속 보상은 기존 API에 반영된다.
- 현재 모바일 변경은 검수 단계이며 운영 반영은 사용자 승인 후 진행한다. 일반 프리뷰 대신 성장 기능이 활성화된 `live-data-preview` 산출물을 사용한다.
- 모바일 성장 가이드는 검색 헤더 대신 내 페이지로 돌아가는 링크를 표시한다. 7개 휴지를 세로 목록과 오른쪽 레벨 눈금으로 정리하고, 선택 등급과 닉네임 예시를 작게 제공한다.
- 경험치 가이드는 보상과 지급 빈도를 먼저 표시하고, 실제 회원 기준 목표 계산기와 구간별 누적 XP 표를 유지한다. 데스크톱의 공통 헤더와 기존 배치는 유지한다.

## 모바일 내 업적

- 동네 배지·지역 메달을 스티커북으로 제공한다. 지역 선택, 전체·획득·미획득 필터, 획득일·지급 XP·조건을 확인하는 상세 화면을 지원한다.
- 소유 여부는 서버 지급 목록으로만 판단한다. 메달 조건과 지역 진행률은 서버의 현재 대상 동네 수·화장실 수를 사용하며, 이전 정책의 획득 기록도 유지한다.
- 도안 256종과 현재 정책의 수집 대상 수는 다를 수 있다. API가 미획득 대상 코드 목록을 제공하지 않으므로 도안 총수를 완료율 분모로 사용하지 않으며, 조건에는 수집 대상 동네 기준임을 명시한다.
- 실제 API를 쓰는 [내 업적 프리뷰](https://preview.geupddong.com/?tab=account&view=achievements)에서 사용자 검수를 진행한다. 기존 접속 보상 API 외에 별도 지급이나 기록 변경은 추가하지 않는다.
- 운영 배포는 별도 사용자 승인 후 진행한다. [모바일 검수 PR](https://github.com/toilet-project/toilet-web/pull/367)에서 구현·배포 검증과 남은 검수 사항을 관리한다.

- [x] 서버 계약 대조 및 가상 회원 응답으로 데스크톱 마이페이지·헤더·등급 이미지·레벨 계산 통합 확인
- [x] 한국어·영어 외 성장 안내 문구 번역 추가
- [x] 최신 main 통합 및 기존 모바일 계정 화면 전환·패널 지연 로딩 유지
- [x] Linux Worker CI에서 일반 미리보기·성장 활성 운영 후보·캐시 릴리스 간 호환 검사 통과
- [x] 컴파일된 성장 설정, 소스 추적 manifest, 운영 후보 산출물 검증
- [x] 서버 정책 활성화·기존 리뷰 소급 반영 및 재실행 시 추가 지급 없음 확인
- [x] 검증된 웹 후보 업로드 및 기존 운영 바인딩·호환성 설정 일치 확인

후보 업로드는 운영 트래픽 전환과 별개다. 가상 회원 응답을 사용한 통합 확인 역시 실제 계정·운영 브라우저 검증을 대신하지 않는다.

## 운영 반영 순서

서버 정책·소급 반영과 실제 서비스 배포는 아래 순서로 확인한다. 이 절차는 완료 상태를 표시하는 체크리스트가 아니다.

1. 최신 `main`을 통합한다. 계정 화면의 모바일 전환 유지와 패널 지연 로딩, Next.js 갱신을 보존한다.
2. 성장 API·정책·기존 리뷰 소급 반영을 완료하고 회원 요약을 확인한다.
3. 같은 소스의 Linux CI에서 성장 기능이 켜진 `live-data-preview`와 `production-candidate`를 빌드한다. 일반 미리보기와 가상 리뷰 후보는 끈 상태로 검증한다.
4. 추출한 산출물의 소스·설정·빌드 ID를 기존 검증 도구로 확인하고 `--expect-member-growth=true`를 추가한다. 릴리스 manifest의 `features.memberGrowth`는 컴파일된 Next 설정에서 읽으며 빌드 요청과 다르면 실패한다.
5. 미리보기에서 `/account`, `/growth/ranks`, `/growth/levels`, 상단 프로필·메뉴, 실제 회원 경험치·배지와 로그아웃 상태를 확인한다. 프로필 사진·닉네임은 기존 API를 사용한다.
6. 검증된 후보를 `opennextjs-cloudflare upload --config wrangler.production.jsonc --keep-vars`로 업로드하고, 버전 설정과 기존 운영 트래픽이 유지되는지 확인한다. 업로드 과정에는 원격 캐시·정적 파일 준비가 포함된다.
7. 서버 검증과 롤백 대상 확인이 끝나면 해당 버전만 `wrangler versions deploy`로 전환한다. 기존 도메인 경로는 별도 관리하므로 일반 `deploy`나 `triggers deploy`로 덮어쓰지 않는다. 운영 주소에서 같은 읽기 항목과 오류·비활성 응답을 확인한다.

배포 후 공개 경로·언어별 가이드·원본 이미지 확인은 `node scripts/verify-member-growth-public.mjs https://preview.geupddong.com` 또는 운영 주소로 실행한다. 이 검사는 쿠키나 회원 API를 사용하지 않으며 로그인 회원 경험치·접속 보상·프로필 수정 확인을 대신하지 않는다.

`NEXT_PUBLIC_GROWTH_ENABLED`는 공개 빌드 설정이다. Worker 런타임 변수만 바꿔서는 켜지지 않는다. 서버 기능이 비활성이면 웹 설정이 켜져도 경험치를 임의로 표시하지 않는다. CI는 빌드·검증·산출물 생성만 수행한다.
