# 모바일 내비게이션·내 페이지 UX (#192)

## 구현

- 지도·커뮤니티(coming soon, 비활성)·알림·내 페이지 4개 하단 탭. 모바일 footer 제거, 하단 safe-area는 내비게이션 자체 영역으로 확보한다.
- 지도 DOM/타일/선택 상태를 유지한 채 다른 탭에서는 지도 영역을 숨기고 inert 처리한다. 탭을 바꿨다고 지도를 다시 생성하거나 상세 URL을 변경하지 않는다.
- 헤더의 내 제보·계정 항목은 내 페이지로 이동. 모바일 메뉴는 이용약관·문의로 단순화한다. PC 헤더는 유지한다.
- 비로그인 알림/내 페이지에는 로그인 랜딩만 노출한다. 가짜 개인 데이터나 비로그인 사용자용 제보 API 요청은 만들지 않는다.
- OAuth 시작 전에 원래 모바일 탭 이름만 sessionStorage에 저장한다. 성공/필수 동의 완료 후 복귀하고 키를 제거한다. 기존 제보 대상 복귀 로직은 유지한다.
- 알림의 선택 상자는 우선 내 제보만 제공한다. 기존 제보 상태 필터/관리자 메모를 재사용하며, 받은 알림·읽음 처리도 별도 버튼으로 유지한다.
- 원형 기본 아바타 및 닉네임, 톱니 버튼, 닉네임 편집. 기존 프로필 API에 사진 필드가 없어 실제 소셜 사진을 임의 수집하지 않는다. 사진 수정은 구현 예정으로 명시한다.
- 닉네임 PATCH는 API feature/self-profile-nickname에 구현. 세션 만료 응답은 로그인 랜딩으로 전환한다. 운영 API를 먼저 배포해야 실제 저장이 가능하다.
- `/policies/all`에서 기존 세 정책을 섹션별로 함께 표시한다. 원문·시행일·동의 버전·개별 정책 URL은 유지한다. 정책 법률 내용이나 수집 항목 변경은 없다.

## 검증 및 미완료 항목

- lint/typecheck, 기존 Node 테스트 59건 통과.
- Chromium·WebKit 모바일 375×667, 390×844, 가로 844×390: 익명 접근 차단, OAuth 탭 복귀, 닉네임 저장, 내 제보/관리자 메모, 알림 창, 로그아웃, 통합 정책 페이지 확인. 인증/수정은 브라우저 fixture이며 운영 쓰기 0건.
- PC 1920/1440/1024/700px 및 resize: 중앙 헤더/메뉴 접근성/카드 최초 프레임 위치/지도 유지 통과.
- API 닉네임·컨트롤러 테스트 11건 통과. API 전체 테스트는 기존 Docker/H2 제약으로 5건 실패, 4건 생략되어 전체 통과가 아니다.
- 실제 iPhone Chrome의 키보드·safe-area·회전·핀치 확대는 사용자 확인이 필요하다. WebKit 자동화가 실제 아이폰 앱 검증을 대신하지 않는다.
- 운영에는 PC #191만 반영했다. 모바일 feature/PR은 검토 대기이며 API 선행 배포 후 웹 배포한다. 실제 프로필 사진 연동은 별도 결정 사항이다.

## 모바일 디자인 보완 (2026-09-06)

- 지도 헤더는 60px 한 줄로 브랜드 → 주소 검색 → 로그인 → 메뉴 순서로 정렬한다. 후속 사용자 검토에서 키보드를 내려도 확장된 입력창이 남는 문제가 확인되어, 포커스에 따른 입력창 확대를 제거했다. 입력창은 40px 높이와 16px 글씨를 유지하고 결과 목록만 아래에 표시한다. blur·검색 결과 선택·Escape·탭 변경 시 결과 목록을 닫는다.
- 검색창과 메뉴 버튼의 14px 모서리·연한 배경을 맞춘다. 하단 메뉴의 아이콘 크기·선 굵기·라벨 기준선을 통일하고, 선택한 아이콘에만 작은 연녹색 배경을 사용한다. coming soon은 테두리에 걸치는 배지 대신 커뮤니티 이름 아래에 표시한다.
- 단일 상세·동일 위치·지역 목록 카드의 최대 높이에서 상단 컨트롤과 간격을 포함한 80px를 제외한다. 상세 확장 시 상단 버튼을 가리지 않고 카드 내부를 스크롤한다.
- 단일/동일 위치 카드 버튼은 로그인 여부와 관계없이 `정보 제공하기`로 표시한다. 기존 인증 유도와 원래 제보 대상 복귀 로직은 유지한다. 로그인 창에는 주아체 급똥 로고와 `로그인 · 간편가입` 제목을 사용한다.
- 내 페이지는 아바타와 닉네임을 가로로 배치하고 메뉴를 구분선 있는 행으로 정리한다. 불필요한 프로필 홍보 문구와 중첩된 카드 테두리를 제거한다.
- 로그인 화면은 큰 외곽 카드 없이 간결하게 구성하고 Google/Kakao 아이콘과 버튼 규격을 맞춘다.
- 알림 제목·카테고리는 같은 줄에 배치하고, 제보 목록에서는 화장실명·상태를 우선 표시한다. 받은 알림과 기존 상세 메모 기능은 유지한다.

### 이번 보완의 실제 검증 범위

- 후속 수정: lint/typecheck 및 Node 63건 통과(새 구조 회귀 검사 4건 포함). 390×844·320×667에서 확장 카드 상단과 두 지도 버튼 하단의 16px 간격 및 가로 넘침 없음을 확인했다. 검색 전/중 입력 높이 40px 유지, 검색 결과 선택/닫기, 정보 제공 버튼의 로그인 모달 유도를 확인했다. 실제 iPhone의 소프트 키보드 동작은 재확인이 필요하다.
- lint/typecheck 및 Node 테스트 59건, diff 공백 검사 통과.
- 개발 브라우저 320×667·390×844: 한 줄 헤더, 하단 메뉴, 비로그인 내 페이지 확인. 390px에서 검색 확장·검색 결과 노출·닫기를 확인했다.
- 1440×900에서 기존 데스크탑 헤더·목록 및 모바일 메뉴 숨김을 확인했다.
- 로그인 후 프로필 배치는 실제 컴포넌트를 서버에서 정적 렌더링한 예시 계정으로만 시각 검토했다. 운영 로그인·프로필 저장은 실행하지 않았다.
- 앞 절의 Chromium/WebKit 전체 기능 검증은 이전 커밋의 결과다. 이번 디자인 변경에 대해 해당 전체 회귀 스크립트를 다시 실행했다고 간주하지 않는다. 실제 iPhone 및 배포 후 인증 통합 검증은 남아 있다.
