# 지도 상세 카드 부분 로딩

## 변경 범위

- 목록·마커에서 받은 화장실명, 구분, 좌표 기반 거리는 즉시 표시한다.
- 아직 받지 않은 개방시간·주소·시설 정보는 해당 영역에만 정적인 로딩 표시를 사용한다. 알 수 없는 값을 0대·미설치로 표시하지 않는다.
- 지도에서 선택하면 브라우저 상세 API 조회와 Next.js URL 이동을 함께 시작한다. API 응답이 먼저 오면 페이지 응답을 기다리지 않고 카드를 완성한다.
- 직접 상세 URL로 진입하는 경우 서버 HTML, 메타데이터, JSON-LD와 초기 상세 데이터 재사용을 유지한다.
- 지도 재생성, 중심 이동, 기준점 변경은 추가하지 않는다.

## 최신성·안전성

- 공개 상세 데이터만 지도 컴포넌트 메모리에 최대 30건·30초 보관한다. 로컬 저장소에는 저장하지 않으며 읽기로 유효기간을 연장하지 않는다.
- 같은 ID의 최신 브라우저 응답이 있으면 뒤늦은 서버 페이지 응답으로 덮어쓰지 않는다.
- 선택 변경·닫기·컴포넌트 해제 시 이전 요청을 취소하고 늦은 응답을 무시한다. 10초 제한과 재시도 버튼을 제공한다.
- 상세 응답 ID를 검사한다. 제보 버튼은 실제 상세 정보를 받은 뒤에만 활성화한다.

## 비용과 한계

이 변경은 전체 상세 페이지 전환 대기 시간을 카드 표시의 필수 조건에서 제거하는 개선이다. 최초 선택에서는 브라우저 API 요청과 Next.js 페이지 요청이 함께 발생할 수 있다. 필드별 차분 API를 새로 만든 것은 아니며 상세 API는 기존 응답 형식을 유지한다. 서버 측 캐시와 30초 클라이언트 캐시를 활용하지만 요청 수가 항상 줄어든다고 보장하지 않는다.

30초 동안은 이전 상세 값이 재사용될 수 있다. 이 정책은 제보 승인 직후 즉시 일관성을 보장하는 정책이 아니다. URL 전환·메타데이터는 Next.js의 서버 응답 완료를 기다린다. 브라우저 API가 실패해도 서버 상세 응답이 성공하면 표시를 복구할 수 있다.

## 검증

- `pnpm run lint`, `pnpm run typecheck`, `pnpm test`.
- `tests/detail-progressive-regression.cjs`: 고정 로컬/preview 주소만 허용. 상세 API 700ms, 페이지 응답 2초 지연을 주입해 기존 정보 선표시, 페이지보다 빠른 상세 완성, 캐시 재사용, 연속 선택, 닫기, 동일 좌표 상세, 실패·재시도를 검사한다. 실제 업무 데이터 쓰기는 차단한다.
- 기존 로컬 회귀 검사: 375×667, 390×844, 430×932, 1440×1000에서 카드·제보 로그인 안내·브라우저 뒤로/앞으로·지도 DOM 유지 확인.
- Chromium 검사이며 실제 iPhone Safari 검증이나 운영 배포 후 성능 측정과 동일하지 않다. 지연 주입 검사는 동작 보장용이며 운영 속도 수치로 해석하지 않는다.
