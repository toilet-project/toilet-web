# 지도 첫 진입·필터 전환 개선

## 목적과 적용 범위

홈 지도와 편의시설 필터의 대기를 줄인다. 실데이터 프리뷰에서 검수하며 운영 배포는 별도 승인 후 진행한다.

## 확인한 병목과 변경

| 병목 | 변경 |
| --- | --- |
| 홈의 언어 전환·상세 컴포넌트가 전국 시·군·구 경계 자료까지 즉시 가져옴 | 상세 본문과 지역 주소 계산을 필요할 때 로딩. 국내 좌표 검사는 기존의 정확한 시·도 경계로 유지 |
| 지도 화면 코드를 받은 다음 SDK 다운로드 시작 | 경로 등록 시 해당 언어의 SDK 준비를 화면 코드와 병렬 시작 |
| 초기 지도·크기 조정의 같은 범위 요청이 앞선 요청을 취소 | 지도·범위·확대 수준·목록 모드·필터 범위가 모두 같은 진행 중 요청만 합침 |
| 각 구역이 전역 캐시 변경 여부를 따로 두 번 읽음 | 한 요청의 구역들이 최초 조회를 공유하고 모든 결과 뒤에 다시 확인. 변경 시 전체 결과 재조회 |
| 지도 SDK 실패 후 남은 스크립트로 재시도 불가 | 실패·시간 초과 시 스크립트 정리, 지도 초기화 재시도 제공 |

## 검증 근거

- 동일한 Next.js 버전과 실데이터 프리뷰 기능 설정으로 개선 전·후 빌드의 홈 HTML이 요구하는 고유 JS 파일을 비교했다. 쿼리 문자열은 동일 파일로 정규화했다.
- 초기 JS는 약 **1.64 MB → 0.84 MB**, 파일별 gzip 합계는 **472 KB → 266 KB**다. 브라우저 전체 로딩 시간이나 지도 표시 시간의 감소율을 뜻하지 않는다. SDK·타일·후속 비동기 파일과 통신 환경은 별도다.
- 따뜻한 캐시의 저장소 GET은 **4구역 12 → 6회**, **16구역 48 → 18회**다. 캐시 미스·무효화 경합에서는 추가 조회할 수 있다.
- 전역·구역 수정/삭제, 동시 초기 저장, 갱신 중 무효화, 프리뷰 자료 버전, 개인별 즐겨찾기 격리를 시험한다. 경계 자료 분리 후 지역 주소·다국어·섬/해외 좌표 판정도 검증한다.

## 유지하는 제한과 후속

- 요청 완료 후 지도 결과를 새로 캐시하지 않는다. 계정별 즐겨찾기와 위치는 공유 응답 캐시에 저장하지 않는다.
- 데이터 무효화·기존 캐시 보존 기간·API 권한·국내 판정 범위를 바꾸지 않는다. 필터 전환 시 이전 조건의 마커를 새 결과처럼 표시하지 않는다.
- 전국 단위 필터 집계의 자료 압축 해제·전체 순회는 남아 있다. 별도 계측과 무효화 설계 검토 후 개선한다.
- GPS 허용 여부와 응답 시간, 외부 지도 SDK/타일 속도 때문에 모든 기기에서 같은 표시 시간을 보장하지 않는다. 실데이터 프리뷰와 모바일 실기기 확인, 운영 승인 후 계측이 필요하다.
