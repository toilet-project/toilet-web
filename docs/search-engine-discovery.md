# 다국어 검색엔진 노출 확장

## 적용 순서

1. Google Search Console과 네이버 Search Advisor는 기존 운영을 유지한다.
2. Bing Webmaster Tools에 `https://geupddong.com`을 등록하고 `/sitemap.xml`을 제출한다. Google Search Console 가져오기를 우선 사용한다.
3. Cloudflare Crawler Hints를 보조 경로로 사용한다.
4. 내부 캐시 무효화 이벤트가 공개 시설 변경을 확정한 뒤 IndexNow로 변경 URL을 알린다.
5. Yandex는 IndexNow 수신 결과와 실제 유입을 관찰한 뒤 별도 웹마스터 등록을 결정한다. Baidu는 중국 본토 접근성과 계정 검증을 먼저 확인한다.

Yahoo Japan, DuckDuckGo, Ecosia는 별도 사이트 등록보다 Google/Bing 색인과 사이트맵을 통해 발견되는 경로를 우선한다.

## IndexNow 안전 조건

- `SITE_INDEXABLE=true`와 `INDEXNOW_ENABLED=true`가 모두 충족된 운영 Worker에서만 동작한다.
- `geupddong.com`의 지역·이름을 포함한 공개 상세 정식 URL과 알려진 시군구 정식 URL만 허용한다. `noindex`인 숫자 시설 URL, 정식 시군구 경로와 다른 주소, API, 관리자, 로그인, 내부 캐시 경로, 쿼리 문자열은 거부한다. 지역이 확인되지 않아 숫자 URL로 대체되는 시설도 제출하지 않는다.
- 수정 이벤트는 현재 공개 API를 새로 읽어 번역 이름과 주소가 모두 있는 언어의 대표 URL만 제출한다. 갱신 전 공유 캐시에 유효한 공개 상세 정보가 남아 있다면 이전 정식 URL도 함께 알린다.
- 삭제·비공개 이벤트는 갱신 전 공유 캐시에서 실제 이전 정식 URL을 확인한 경우에만 제출한다. 이전 값이 없으면 이름이나 지역을 추측해 URL을 만들지 않고 사이트맵 제거와 검색엔진 재방문에 맡긴다.
- 시군구는 한 이벤트에서 영향 범위가 1~4개로 특정되고 갱신 전 지역 마커 캐시가 유효할 때만 전후 서버 목록을 언어별로 비교한다. 표시되는 시설 이름·링크가 달라진 정식 지역 URL만 후보가 된다. 비교용 원본 조회는 읽기 전용이며 방문자용 지역 캐시를 채우지 않는다. 더 넓거나 불확실한 범위의 이벤트는 캐시만 갱신한다.
- 한 수신 배치에서 URL을 중복 제거하며 IndexNow 제한인 10,000개를 넘기지 않는다.
- 429와 5xx 및 일시적인 네트워크 오류는 제한 횟수만 재시도한다. 알림 실패는 DB 변경, 캐시 무효화, outbox ACK를 실패시키지 않는다. 실패는 키·URL을 기록하지 않고 HTTP 상태/시간 초과/네트워크 오류로 구분한다.
- 키는 인증 비밀이 아니라 도메인 소유 확인용 공개 값이며 루트 정적 파일로 제공한다.

현재 지역 외 일반 페이지(홈·정책 등)의 콘텐츠 변경 이벤트와 영속 재시도 큐는 구현되지 않았다. 캐시 무효화나 배포 자체를 이 페이지들의 변경 증거로 취급하지 않는다. 원인 구분 변경과 지역 알림은 [PR #340](https://github.com/toilet-project/toilet-web/pull/340)에만 있으며 운영에는 아직 적용하지 않았다. 자세한 미완료 범위는 [WBS #321](https://github.com/toilet-project/toilet-web/issues/321)에서 추적한다.

## 2026-10-03 읽기 전용 재점검

- 시설 53585의 6개 언어 정식 페이지는 모두 HTTP 200, `index, follow`, self-canonical이다. Bing은 한국어·영어·중국어 간체·홍콩 번체를 발견했지만 아직 크롤링 전이며 일본어·대만 번체는 미발견이다. 9/28 표본과 같다.
- Bing 사이트맵은 9/29 성공, 오류·경고 0이다. 표시된 발견 URL 37개는 sitemap index의 하위 파일 수이며 시설 색인 수가 아니다. 상세의 하위 사이트맵 목록은 여전히 비어 있어 실제 처리 범위는 확정할 수 없다. IndexNow Insights는 안내 화면으로 통계가 없다.
- 최근 3일 Worker 검색 화면에는 IndexNow 오류 300건·성공 0건이 표시되며 데이터량 때문에 불완전할 수 있다는 안내가 있다. 10/3에도 실패 표본이 있다. 이는 전체 전송 실패율이 아니며 기존 오류 직렬화에 응답 코드가 없어 원인을 확정할 수 없다.
- 운영 키 파일의 HTTP 200·본문 일치와 공개 API `UP`를 확인했다. URL·키를 넣지 않은 GET 비교에서 `/IndexNow`와 `/indexnow`는 같은 400 응답을 반환했다. 경로 대소문자를 기존 실패의 원인으로 단정하지 않는다. 공식 프로토콜의 `/indexnow` 표기는 유지한다.
- URL 제출·사이트맵 재제출·운영 데이터 수정은 하지 않았다. 다음 단계는 진단 변경 운영 적용 후 자연 변경 이벤트의 HTTP 상태·시간 초과·네트워크 분류 확인이다. 배포·전송 성공과 검색엔진 색인은 별도로 판정한다.

## 운영 전환과 되돌리기

미리보기 설정의 `INDEXNOW_ENABLED`는 `false`로 유지하고, 운영은 2026-09-23 키 파일 접근성·Bing 사이트 등록·격리 검증을 마친 뒤 `true`로 전환했다. 운영에서는 서명된 공개 데이터 변경 이벤트만 URL 알림을 예약한다. 문제가 있으면 운영 값을 `false`로 되돌려 새 Worker 버전을 배포한다. 이때 캐시 무효화와 페이지 제공은 그대로 유지된다.

대량 전체 URL 제출은 하지 않는다. 전체 목록은 사이트맵이 담당하고 IndexNow는 새로 추가되거나 수정·삭제·비공개 전환된 URL만 알린다.
