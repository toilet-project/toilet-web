# 다국어 검색엔진 노출 확장

## 적용 순서

1. Google Search Console과 네이버 Search Advisor는 기존 운영을 유지한다.
2. Bing Webmaster Tools에 `https://geupddong.com`을 등록하고 `/sitemap.xml`을 제출한다. Google Search Console 가져오기를 우선 사용한다.
3. Cloudflare Crawler Hints를 보조 경로로 사용한다.
4. 내부 캐시 무효화 이벤트가 공개 시설 변경을 확정한 뒤 IndexNow로 변경 URL을 알린다.
5. Yandex는 IndexNow 수신 결과와 실제 유입을 관찰한 뒤 별도 웹마스터 등록을 결정한다. Baidu는 중국 본토 접근성과 계정 검증을 먼저 확인한다.

Yahoo Japan, DuckDuckGo, Ecosia는 별도 사이트 등록보다 Google/Bing 색인과 사이트맵을 통해 발견되는 경로를 우선한다.

## IndexNow 안전 조건

- `SITE_INDEXABLE=true`와 `INDEXNOW_ENABLED=true`가 모두 충족된 운영 Worker에서만 동작한다.
- `geupddong.com`의 지역·이름을 포함한 공개 상세 정식 URL과 알려진 시군구 정식 URL만 허용한다. `noindex`인 숫자 시설 URL, 정식 시군구 경로와 다른 주소, API, 관리자, 로그인, 내부 캐시 경로, 쿼리 문자열은 거부한다. 지역이 확인되지 않아 숫자 URL로 대체되는 시설도 제출하지 않는다.
- 수정 이벤트는 현재 공개 API를 새로 읽어 번역 이름과 주소가 모두 있는 언어의 대표 URL만 제출한다. 갱신 전 공유 캐시에 유효한 공개 상세 정보가 남아 있다면 이전 정식 URL도 함께 알린다.
- 삭제·비공개 이벤트는 갱신 전 공유 캐시에서 실제 이전 정식 URL을 확인한 경우에만 제출한다. 이전 값이 없으면 이름이나 지역을 추측해 URL을 만들지 않고 사이트맵 제거와 검색엔진 재방문에 맡긴다.
- 시군구는 한 이벤트에서 영향 범위가 1~4개로 특정되고 갱신 전 지역 마커 캐시가 유효할 때만 전후 서버 목록을 언어별로 비교한다. 표시되는 시설 이름·링크가 달라진 정식 지역 URL만 후보가 된다. 비교용 원본 조회는 읽기 전용이며 방문자용 지역 캐시를 채우지 않는다. 더 넓거나 불확실한 범위의 이벤트는 캐시만 갱신한다.
- 한 수신 배치에서 URL을 중복 제거하며 IndexNow 제한인 10,000개를 넘기지 않는다.
- 429는 즉시 재시도하지 않는다. `Retry-After`와 최소 10분 중 더 긴 대기 시간을 기존 R2의 공통 상태에 저장하며 상세·시군구 알림이 함께 따른다. 대기 중에는 알림용 원본 조회도 생략한다. 조건부 저장으로 동시 요청이 대기 시간을 줄이지 못하게 한다. 공유 상태를 읽지 못하면 해당 알림을 중단한다. 이 상태는 URL 재처리 큐가 아니므로 대기 중 누락된 변경을 자동 복구하지는 않는다.
- 현재 운영의 기존 경로는 5xx 및 일시적인 네트워크 오류만 제한 횟수로 재시도한다. 알림 실패는 DB 변경, 캐시 무효화, outbox ACK를 실패시키지 않는다. 아래 영속 재전송 초안은 저장 실패 시 ACK를 보류하는 별도 계약이며 아직 비활성이다. 키·URL 없이 HTTP 상태/시간 초과/네트워크 오류/대기 종료 시점을 구분한다. 429 대기는 [공식 FAQ](https://www.indexnow.org/faq)의 요청 제한 지침을 따른다.
- 요청하지 않은 배치는 `skipped`, HTTP 202는 키 검증 대기, HTTP 200은 접수 성공으로 구분한다. 성공·실패에 전체 알림 처리 시간을 남기며 어느 결과도 실제 검색 색인 완료를 의미하지 않는다.
- 키는 인증 비밀이 아니라 도메인 소유 확인용 공개 값이며 루트 정적 파일로 제공한다.

현재 지역 외 일반 페이지(홈·정책 등)의 콘텐츠 변경 이벤트와 운영 영속 재전송은 연결되지 않았다. 캐시 무효화나 배포 자체를 이 페이지들의 변경 증거로 취급하지 않는다. 진단·제한된 지역 알림·429 대기 보완의 검증과 배포 기록은 [PR #340](https://github.com/toilet-project/toilet-web/pull/340)에 연결한다. 자세한 미완료 범위는 [WBS #321](https://github.com/toilet-project/toilet-web/issues/321)에서 추적한다.

## 영속 재전송 초안 · 연결 구현, 운영 비활성

[PR #375](https://github.com/toilet-project/toilet-web/pull/375)의 구현이다. 운영·프리뷰 모두 `INDEXNOW_OUTBOX_ENABLED=false`이며 Cron 등록도 없다. 기존 운영 경로·R2 사용량은 아직 바뀌지 않는다. 활성화에는 별도 운영 승인이 필요하다.

### 변경 의도 보존과 ACK

1. 서명된 v2·v3 이벤트의 시설 ID·revision·동작을 해시해 `indexnow/intents/v1/`에 먼저 저장한다. 삭제·비공개·이름 변경의 이전 공개 정식 경로와, 최대 4개 시군구의 언어별 목록 해시를 캐시 무효화 전에 확보한다. 전체 시설 응답이나 개인정보는 저장하지 않는다.
2. 저장에 실패하면 **캐시를 변경하기 전에 503을 반환**해 송신자 재시도를 기다린다. 이 경우 캐시 갱신이 잠시 지연될 수 있으며 사용자가 승인한 계약이다. 원본 DB 변경을 취소하는 방식은 아니다.
3. 기존 캐시 갱신을 모두 마친 뒤 의도를 처리 가능 상태로 전환하고 ACK한다. 갱신·상태 전환 실패도 503이며, 재요청은 최초 저장한 이전 주소를 재사용한다. 아직 갱신하지 않은 의도는 자동 소비하지 않는다. revision 없는 v1은 기존 동작을 유지한다.
4. 소비 시 현재 공개 정보와 비교해 URL을 확정하고 `indexnow/outbox/v1/`에 저장한다. 확정 경로는 먼저 동결하므로 이후 원본이 바뀌어도 저장 재시도 내용은 변하지 않는다. 원본 조회 실패를 빈 목록으로 처리하지 않는다. 이전 캐시 부재·넓거나 불확실한 지역 범위는 기존 제한을 유지한다.

### 인증된 실행과 재시도

- Worker의 예약 실행이 기존 캐시 서명 키로 내부 처리 경로에 만료 시간·경로가 결합된 별도 HMAC 요청을 만든다. 공개 무인증 실행은 거부한다. 프리뷰는 검색 노출과 외부 전송 차단을 유지한다.
- `indexnow/control/v1/`의 조건부 소유권과 목록 cursor로 인스턴스 간 동시 실행을 막고 순환 진행을 보존한다. 실행 간 최소 10분을 두며 한 번에 의도 최대 10개(원본 조회 동시 4개)와 전송 작업 최대 10개(작업당 최대 100경로)를 처리한다. 전송은 실행당 1회만 시도한다.
- 각 목록에서 최대 1,000개를 순회하되 완료 상태의 원자적 R2 메타데이터로 불필요한 본문 읽기를 생략한다. R2 응답의 `truncated`·cursor로 다음 페이지를 판단하며 개수가 적다는 이유로 끝으로 간주하지 않는다. 메타데이터가 없는 이전 기록은 검증된 본문 읽기로 대체한다. [R2 목록 계약](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/#r2listoptions)을 따른다.
- 실행 시작 20초 뒤에는 새 작업을 시작하지 않는 소프트 예산을 둔다. 진행 중인 원본 조회·전송에는 기존 5초 제한이 적용되지만 R2 작업을 강제 취소하는 전체 실행시간 보장은 아니다. 시간 부족으로 전송 전 양보한 작업은 시도 횟수를 소진하지 않는다. cursor 순환으로 건너뛴 작업을 재방문한다.
- 공통 대기를 조회 전과 전송 전에 검사한다. 429의 종료 시각과 10분부터의 점진적 재시도를 보존한다. 공통 대기 검사만으로 시도 횟수를 소진하지 않는다. 의도 해석·저장과 원격 전송은 각각 최대 8회 후 보류하며, 영구 4xx 거절도 삭제하지 않고 남긴다.
- 소유권은 2분 후 회수할 수 있다. 원격 접수 직후 결과 저장 전에 장애가 발생하면 중복 전송 가능한 최소 1회 전달 방식이다. 서로 다른 실행의 같은 URL까지 전역 중복 제거하지 않는다. HTTP 200·202는 접수이며 크롤링·색인 완료가 아니다.
- 방문자 캐시 키·TTL·삭제/무효화 대상은 변경하지 않는다. 추가 저장·목록 순회 비용은 위 별도 접두사에서만 발생하며 활성화 전에는 발생하지 않는다.

### 보류 확인·개별 복구·보관 정책

- 별도 경로 서명이 필요한 `/_internal/indexnow/manage`에서 상태 조회와 페이지당 최대 20개 기록 검사를 제공한다. 응답은 상태·마지막 HTTP 상태·시도/복구 횟수·처리 시각 위주이며 주소 목록과 개인정보는 노출하지 않는다. 최근 실행의 보류·오래된 갱신 대기 수는 **순회 표본**이지 전체 건수나 0건 보증이 아니다. 손상·읽기 실패 기록은 `unreadable`로 구분한다.
- 복구는 원인 검토 후 보류 기록 한 개의 키·현재 ETag·명시적 확인으로만 한다. 동시 변경 시 거부하며, 같은 확인을 재전달해도 중복 복구하지 않는다. 원래 경로는 유지하고 시도 횟수를 초기화하되 최소 10분 뒤 예약 처리에 맡긴다. 즉시 원격 제출하거나 공통 대기를 우회하지 않는다. 기록당 수동 복구는 최대 3회이며 복구 횟수·시각을 남긴다.
- `staged`는 캐시 갱신 완료가 불확실한 상태이므로 수동 소비·복구를 금지한다. 1시간 이상 남으면 송신자의 서명된 원래 캐시 이벤트 재전달을 점검한다. 이 확인 없이 상태를 강제로 해제하지 않는다.
- 완료된 의도(`done`)와 원격 접수 기록(`received`)은 확인된 완료 시각부터 30일 이상 지난 뒤 순회 시 상세 내용을 요약한다. 각 실행에서 접두사별 최대 2개만 전환한다. 완료 의도는 원래 이벤트·주소를 제거하고, 접수 기록은 경로 개수·지문을 남겨 중복 방지를 유지한다. **레코드 자체를 삭제하지 않는다.** 대기·처리 중·보류 기록과 완료 시각이 없는 이전 기록은 자동 요약하지 않는다.
- 요약 기록을 보존하므로 객체 수 증가와 순회 지연은 계속 관찰해야 한다. 의도 해석의 이론상 상한은 10분당 10건이며 실제 처리량은 대기·재시도·순회·시간 예산에 따라 더 낮다. 대량 변경을 바로 활성화하거나 과거 누락이 모두 복구된다고 판단하지 않는다.

운영자 도구는 `scripts/indexnow-operations.mjs`다. 서명 키는 채팅·명령 인자 대신 승인된 프로세스 환경에서만 전달한다. 기본은 조회 또는 변경 미리보기이며 **현재 비활성 대상은 404가 정상**이다. 아래는 형식 안내이며 이번 작업에서 운영 명령을 실행하지 않는다.

```text
node scripts/indexnow-operations.mjs --target preview --action status
node scripts/indexnow-operations.mjs --target preview --action inspect --kind outbox
node scripts/indexnow-operations.mjs --target preview --action recover --key <검사한 키> --etag <현재 ETag>
```

실제 복구·요약 전환에는 `--confirm-reviewed`가 필요하다. 운영 대상 변경은 별도 승인 후 `--target production --allow-production`까지 명시해야 한다. 경로를 직접 수정하거나 전체 복구·전체 삭제하는 명령은 제공하지 않는다. 관리자는 사이트 세션이 아니라 기존 서명 비밀에 접근 가능한 운영자로 한정된다.

### 검증과 운영 전 남은 조건

- 실제 요청 처리 코드를 격리 실행해 인증 → 저장 → 무효화 → 처리 가능 전환 → ACK와 예약 처리 → 모의 접수 기록을 검증했다. 저장·전환 장애, 송신자 재시도, 재시작, 이전 주소 보존, 동시 소유권, 429·대기·영구 거절, 비활성 프리뷰도 검사한다. 실제 IndexNow 제출이나 운영 데이터 변경은 하지 않는다.
- 격리 검사에서 30일 요약 후 중복 방지, 복구 미리보기·동시 변경 거부·공통 대기·복구 상한, 오래된 `staged` 감시, 완료 이력 1,000개 뒤 새 작업의 순환 처리, 20초 소프트 예산을 확인한다. 컴파일된 Worker의 예약 처리·인증 경로는 외부 전송을 모의 처리하고 로컬 R2/D1만 사용하는 CI 실행기로 추가 검사한다. 실제 트래픽 처리량·장기 객체 수·지연 관측은 운영 전환 후 별도 확인이 필요하다.
- 변경 전 캐시 부재·넓은 지역 범위, 전국·시도·홈·정책의 실제 콘텐츠 변경 감지, 자연 변경 이벤트의 자동 접수는 미완료다. 단순 캐시 갱신·배포를 알림 근거로 삼지 않는다.
- 기능 활성화·Cron 등록·운영 배포는 별도 승인 단계다. 긴급 중단은 `INDEXNOW_ENABLED=false`로 전체 알림을 멈추며 캐시 갱신은 유지한다. 저장 기록을 지우지 않고 보존한 뒤 미처리·갱신 전 상태를 확인해 복구한다. 영속 기능만 끄면 기존 비영속 경로로 돌아가므로 누락 복구 완료로 간주하지 않는다. 요약 기록을 해석하지 못하는 이전 초안으로 되돌릴 때는 영속 기능을 반드시 끄고 기록을 보존한다.

## 2026-10-09 재점검

- 시설 53585의 6개 언어 공개 경로에서 HTTP 200과 현재 canonical 주소를 다시 확인했다. Bing의 현재 정식 주소 검사 결과는 한국어·영어·대만 번체·홍콩 번체 발견 후 크롤링 전, 일본어·중국어 간체 미발견이다. 아직 모두 미색인이므로 Bing 선택 canonical은 확인되지 않는다. 이전 언어별 기록과의 차이는 주소 표기·변경 가능성을 함께 검토하며 색인 감소로 단정하지 않는다.
- Bing 사이트맵은 오류·경고 없이 성공이며 루트 마지막 처리일은 10/2다. 하위 35개·약 272.1K URL 발견을 유지하고 일부 하위 파일은 10/7까지 재수집됐다. 공개 sitemap index의 하위 파일 37개와 처리 목록의 차이는 후속 관측 대상이다. 검색 실적 화면은 노출 4회·클릭 0회이며 발견 수는 실제 검색 색인 수가 아니다.
- 최근 24시간 Worker 검색 화면에서 10/9 00:24·00:30 KST 실패 표본을 확인했다. 00:30의 동일 캐시 갱신 요청은 HTTP 200, CPU 122ms·전체 4,407ms였다. 화면은 고용량·샘플링 경고가 있으므로 집계 수치를 전체 전송 실패율로 해석하지 않는다.
- 기존 운영 산출물 대조로 과거 오류가 HTTP 비성공 응답 분기임을 확인했다. 승인받은 진단 변경을 운영에 적용한 뒤, 이미 전달된 공개 시설 이벤트 1건을 재전달해 **IndexNow HTTP 429**와 약 1.6초의 알림 처리 시간을 확인했다. 같은 캐시 갱신 응답은 HTTP 200이며 원본 DB 행은 바뀌지 않았다. 이것은 운영 Worker 실행 경로의 재현 결과이며 자연 발생 이벤트 성공이나 과거 모든 실패의 원인을 증명하지 않는다. 요청 제한의 정확한 산정 기준은 아직 확인하지 못했다.
- 운영 키 파일의 HTTP 200·본문 일치를 확인했다. 시설 53585의 영어 정식 URL **1개만** 로컬 실행 환경에서 비교 제출했다. 10/6 00:11~00:12 KST에 공식 `/indexnow`와 현재 운영 `/IndexNow`가 각각 HTTP 200을 반환했다. 접수는 가능하며 이 표본은 잘못된 키·경로 대소문자 가설을 뒷받침하지 않는다. Worker 실행 환경의 자연 이벤트 성공이나 Bing 색인까지 검증한 것은 아니다.
- 10/9 IndexNow 목록에는 10/6 직접 제출한 영어 주소 1행과 `Self` 출처만 남아 있으며 최근 2시간 제출은 0으로 표시된다. 신규 자동 접수 성공 근거는 확인하지 못했다. 과거 직접 비교 제출 반영을 운영 자동 알림 성공으로 해석하지 않는다.
- 사이트맵 재제출·시설 데이터 수정·전체 URL 제출은 하지 않았다. 429 확인 후 반복 재전달을 중단했고 즉시 재시도 제거와 공통 대기 상태를 보완했다. 자연 변경 이벤트의 자동 접수와 Bing 반영은 별도 확인이 필요하다. 200·202의 의미는 [IndexNow 공식 문서](https://www.indexnow.org/documentation)를 기준으로 구분한다.

## 후속 순서와 범위

1. [PR #340](https://github.com/toilet-project/toilet-web/pull/340)의 진단과 제한된 지역 알림은 사용자 승인 후 운영에 반영했다. 429 보완도 CI·실데이터 프리뷰·운영 검증 결과를 PR에 남긴다. 미리보기의 IndexNow 전송·검색 노출 차단은 유지한다.
2. 요청 제한 해제 후 자연 이벤트에서 자동 접수 성공과 Bing 반영을 확인한다. 직접 제출 200이나 이미 전달된 이벤트 재현으로 이 단계를 대체하지 않는다.
3. [WBS #321](https://github.com/toilet-project/toilet-web/issues/321)에 남은 변경 전 캐시 부재·넓은 범위·영속 재시도·일반 페이지 변경 감지를 진행한다. 미구현 범위는 완료로 표시하지 않는다.
4. 장기 발견·크롤링·Insights 및 하위 사이트맵 처리 관측은 [11월 운영 점검 #117](https://github.com/toilet-project/docs/issues/117)에서 이어간다.

## 운영 전환과 되돌리기

미리보기 설정의 `INDEXNOW_ENABLED`는 `false`로 유지하고, 운영은 2026-09-23 키 파일 접근성·Bing 사이트 등록·격리 검증을 마친 뒤 `true`로 전환했다. 운영에서는 서명된 공개 데이터 변경 이벤트만 URL 알림을 예약한다. 문제가 있으면 운영 값을 `false`로 되돌려 새 Worker 버전을 배포한다. 이때 캐시 무효화와 페이지 제공은 그대로 유지된다.

대량 전체 URL 제출은 하지 않는다. 전체 목록은 사이트맵이 담당하고 IndexNow는 새로 추가되거나 수정·삭제·비공개 전환된 URL만 알린다.
