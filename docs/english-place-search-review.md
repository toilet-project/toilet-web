# 영어 장소 검색 보완 검토

상태: 2026-09-19 원인 검토 기록 / 2026-09-20 Cloudflare 영어 검색 1차 구현으로 후속 진행

> 최신 구현 범위와 데이터 상태는 [영어 장소 검색 · Cloudflare 1차 구성](./cloudflare-english-place-search.md)을 기준으로 본다. 한국어는 기존 카카오 검색을 유지하고, 영어 화면만 자체 검토 데이터와 D1 검색을 사용한다.

## 결론

영어 검색이 모두 차단된 것은 아니다. 현재 검색창은 입력한 문자열을 그대로 카카오 장소 검색에 보내므로, 영문 표기에 따른 매칭·순위 차이와 영문 주소 검색 공백이 있다. 영어 UI 번역만으로 해결되는 영역이 아니다.

카카오 지도는 유지하고 **주요 장소의 검수된 한·영 검색명 보완 → 주소 전용 검색 검토** 순서를 권장한다. 지원하지 않는 이름까지 된다고 안내하지 않는다. 이 문서 작성 당시에는 새 검색 기능을 연결하지 않았으며, 후속 1차 구현에서는 별도 번역 서비스 없이 자체 검토 데이터만 프리뷰 D1에 연결했다.

## 실제 프리뷰에서 확인한 결과

새 비로그인 브라우저에서 운영과 같은 `Places.keywordSearch` 경로를 15회 조회했다. GPS·회원정보는 사용하지 않았고 모든 쓰기 요청을 차단했다. 일부 표본이며 전국 검색 품질을 보장하는 검사가 아니다. 결과 순위는 이후 달라질 수 있다.

| 입력 | 확인 결과 |
| --- | --- |
| Seoul Station / 서울역 | 둘 다 서울역이 첫 결과 |
| Gangnam Station / 강남역 | 둘 다 강남역이 첫 결과 |
| Daejeon Station / 대전역 | 둘 다 대전역이 첫 결과 |
| Gyeongbokgung | 상단 3개가 동명 식당 |
| Gyeongbokgung Palace / 경복궁 | 궁궐 경복궁이 첫 결과 |
| Myeongdong / 명동 | 영문은 남산케이블카, 한글은 명동거리가 첫 결과 |
| restroom / 화장실 | 영문은 일부 화장실, 한글은 숙박 시설도 상단에 나옴. 가까운 화장실 전용 검색으로 볼 수 없음 |
| 영문 도로명 + 건물번호 표본 | 결과 없음. 상세 검색어는 공개 문서에 남기지 않음 |
| 같은 주소의 한국어 입력 | 해당 주소의 시설이 장소 결과로 반환됨. 주소 좌표 검색 자체는 아님 |

코드 근거: `src/App.tsx`의 검색 흐름과 `src/lib/kakaoMap.ts`의 `searchKakaoPlaces`. 장소명·주소 응답은 현재 한국어 원문을 표시한다.

## 권장하는 1차 보완

1. **주요 역·공항·관광지의 검색명 사전**: 공식 명칭을 확인한 공개 장소만 영문/한글 별칭으로 연결한다. 대소문자·공백·하이픈을 정규화하고 중복 결과는 장소 식별자로 합친다. 모든 영어를 한글로 바꾸거나 원문을 덮어쓰지 않는다. 여러 장소를 뜻하는 이름은 후보를 보여 주고 사용자가 고른다.
2. **장소 검색과 주변 화장실 찾기 구분**: `restroom`, `toilet`, `WC` 같은 일반어는 현재 지도 주변 화장실 보기로 안내한다. 위치 권한을 강제로 요구하지 않으며, 사용자가 정한 지도 중심과 실제 현재 위치를 구분한다. 검색으로 이동한 좌표를 리뷰 작성의 현재 위치 증거로 쓰지 않는다.
3. **영문+한국어 후보 표시**: 사전에 검수된 영문명은 한국어 원문과 함께 표시한다. 사전에 없는 결과에는 자동 영문명을 만들어 붙이지 않는다. 결과가 없으면 입력 예시와 현재 지도 주변 보기 대안을 제시한다.

사전은 주요 장소부터 시작하는 제한적 지원이다. 전국 도로명·동네 가게·오타까지 해결하지는 못한다. 구현 전 사용자 실패 검색어를 더 받아 범위와 기대치를 정한다.

## 별도 주소 검색과 다른 대안

- **도로명주소 영문 검색 API**: 공식 주소 서비스는 영문 검색용 API·승인키를 별도로 제공한다. 영문 도로명·건물번호 검색 후보이지만, 관광지/상호 검색을 대신하지 않는다. 승인키, 주소→좌표 연결, 결과 이용·보관 조건과 실패 처리를 확인한 뒤 별도로 연결한다. 이번에 발급·호출하지 않았다. [주소 서비스 공식 답변](https://m1.juso.go.kr/addrlink/qna/qnaDetail.do?bulletinRefSn=136547&currentPage=73&keyword=&noticeMgtSn=136547&noticeType=QNA&noticeTypeTmp=QNA&page=&searchType=)
- **자동번역 후 재검색**: 사전에 없는 입력을 보완할 수 있지만 고유명사 오역과 추가 지연·비용이 있다. 결과가 나왔다는 이유로 정확한 장소라고 간주하지 않는다. 1차 자동번역 미연결 원칙을 유지하며 도입 시 별도 승인한다.
- **Google Places로 검색만 교체**: 지도에 표시하는 Places 결과는 Google 지도에 표시해야 한다는 정책이 있어 카카오 지도와 단순 결합하는 안은 채택하지 않는다. 장소 데이터 저장·캐시에도 제한이 있다. [Google 공식 정책](https://developers.google.com/maps/documentation/places/web-service/policies)

카카오 공식 키워드 검색 규격에는 질의어·위치·범위·정렬 옵션이 있으며, UI 언어를 바꾸는 것으로 검색이 번역되는 설정은 없다. 위치 정렬을 추가하더라도 전국 목적지 검색과 현재 주변 검색을 구분해야 한다. [카카오 공식 문서](https://developers.kakao.com/docs/ko/local/dev-guide#search-by-keyword)

## 속도·캐시·개인정보 원칙

- 직접 관리하는 공개 별칭 사전만 버전별 정적 자산으로 캐시한다. 카카오 결과를 수집해 사전을 만들지 않는다.
- 같은 입력의 중복 요청은 합치고, 늦게 도착한 이전 검색 결과가 현재 입력을 덮지 않게 한다. 검색 중 재시도 폭증을 막는다.
- 임의의 검색어·주소·사용자 좌표를 로그나 통계에 추가하지 않는다. 현재 검색 성공 여부·결과 수 구간 집계는 유지한다.
- 검색 응답의 세션 메모리 재사용도 공급자 조건 확인 후 제한적으로 적용한다. 사용자 입력을 시설 원본 R2 공용 캐시나 장기 검색어 캐시에 넣지 않는다.
- 별칭은 지도 검색을 돕는 값이며 시설 원본 이름·주소·관리자 확정값·리뷰 위치 판정을 변경하지 않는다.

## 구현 승인 후 검증할 항목

- 영문/한글/혼합/대소문자/하이픈/같은 이름의 다른 지역 및 결과 없음.
- 연속 입력·응답 순서 역전·공급자 오류·시간 초과·중복 결과.
- iPhone 영어 키보드·붙여넣기·후보 선택, 언어 전환 후 지도 유지.
- 일반어로 주변 찾기 시 권한 거부·현재 지도 선택과 실제 GPS 분리.
- 운영·관리자 검색은 별도이며 이번 보완 때문에 변경하지 않음.
