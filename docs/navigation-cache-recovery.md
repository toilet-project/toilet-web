# 지도 페이지 전환 캐시 보호

## 증상과 확인 범위

- iPhone Chrome / preview / 월드컵경기장역(13531): 큰 카드가 잠시 보인 뒤 축소되고 기준점이 해당 화장실로 바뀜. 재방문 및 새로고침 후에도 발생한다는 사용자 보고.
- 수정 전 실서버 HTML이 참조한 CSS·JS 14개는 CI 산출물과 SHA-256이 일치했다. 이전 CSS가 서버에서 섞여 반환되는 증거는 발견하지 못했다.
- 현재 RSC 응답의 배포 ID도 일치했다. 그러나 RSC 응답에 브라우저 캐시 제한이 명시되지 않았다.
- Next.js는 RSC 형식·상태·배포 ID 검증 실패나 네트워크 오류 시 전체 문서 탐색으로 대체한다. 전체 로드는 초기 SSR 카드와 화장실 좌표 기반 지도 초기화를 실행한다. 사용자 증상과 부합하는 경로이지만, 사용자 iPhone의 실패 응답을 직접 확보한 것은 아니므로 원인 확정과 구분한다.

## 변경

1. `src/instrumentation-client.ts`에서 hydration 전에 동일 출처 GET RSC 요청에만 `cache: no-store` 적용.
   - 이미 브라우저에 남은 RSC도 읽지 않는다. 응답 헤더만 바꿔 기존 캐시가 해결됐다고 간주하지 않는다.
   - Next의 `_rsc`, 라우터 상태, 배포 헤더, abort, credentials, priority는 보존한다.
   - 일반 API·인증·외부 API·POST에는 개입하지 않는다. 재시도·자동 새로고침 루프를 추가하지 않는다.
2. `custom-worker.mjs`가 OpenNext 처리 후 HTML/RSC 응답을 감싸 브라우저 및 외부 CDN 캐시를 `no-store`로 제한한다.
   - R2 ISR 및 서버 데이터 캐시는 그대로 사용한다. CSS·JS 파일의 hash/immutable 캐시도 유지한다.
   - 본문을 읽거나 버퍼링하지 않고 스트림과 상태·Vary·보안·배포 헤더를 보존한다.
   - `X-Geupddong-Navigation-Cache: no-store-v1`로 실제 배포 적용을 확인할 수 있다.
3. 지도 내 탐색 시작 및 pagehide 전에 탭의 sessionStorage에 지도 중심/배율/거리 기준점/기준점 종류/현재 위치/카드 상태를 짧게 보관한다.
   - 기존 5분 TTL 및 경로 일치 검증을 재사용하고 복원 후 소비한다. 좌표를 서버에 보내지 않는다.
   - 새 카드 선택 시 펼침 상태는 초기화하되 기준점은 유지한다. 일반 새로고침 시 카드 펼침 상태를 보존한다.
   - 지도 이외 탐색에는 스냅샷을 제거한다. 저장소가 차단돼도 탐색 자체를 막지 않는다.
4. 로컬 기술 진단 이력(문서 시작, 라우트 시작, RSC 실패 종류·상태·클라이언트 버전)을 최대 20건 보관한다.
   - 키: `geupddong.navigation-diagnostics.v1`. 쿼리·좌표·계정·토큰·응답 본문은 기록하지 않는다. 외부 전송 없음.

## 검증

- `pnpm run lint`, `pnpm run typecheck`, `pnpm test`: 로컬 통과(93개).
- 신규 테스트: 이전 RSC가 있는 모의 캐시, Request/URL 입력, abort·헤더 유지, 비대상 요청 미변경, 실패 및 배포 변경 진단, 스트림·immutable 캐시 유지, 지도 경로 제한.
- Linux Workers preview/production-candidate 빌드 통과: Actions `34017983491`. CodeQL `34017983432` 통과.
- preview Worker `1f1a3499-4da4-4d07-831b-705010de18ee`에 배포. 코드 커밋 `e8382d20ae9e416a6ec67a6ae0b14a3ece744762`, CI merge `e5f415f850001299c224c66eb08ccb3817d05da9`.
- 실응답: `/toilet/13531` HTML 및 RSC 200, 세 캐시 헤더 모두 no-store, 보호 헤더 v1 확인. RSC `x-nextjs-cache: HIT`으로 내부 캐시 유지 확인. CSS `public,max-age=31536000,immutable` 유지.
- 기존 캐시를 지우지 않은 브라우저 390×844 화면: 노은119안전센터 검색 기준점 → 월드컵경기장역 210m → SK허브 430m → 월드컵경기장역 210m. 카드 높이 각각 약 249.43px.
- 실제 브라우저 reload 후 월드컵경기장역 210m 및 카드 높이 복원. 이후 SK허브 선택 → 브라우저 뒤로가기에도 210m 유지. 검사 시 콘솔 오류 없음.
- 이전 런타임으로 연 탭에서 새 배포 시점을 사이에 둔 선택은 문서 재로드와 0m 초기화를 보였다. 이는 이전 코드의 배포 경계 동작이며, 새 코드로 부팅한 뒤의 검증과 구분한다.
- 모의 캐시 테스트는 iPhone Chrome 실기기의 캐시를 직접 검사한 것이 아니다. 실기기 최종 확인 전 증상 완치로 단정하지 않는다.

## 배포 및 한계

- 이번 적용 대상은 preview뿐이다. production-candidate 설정에도 같은 진입점을 포함하지만 운영 공개 배포를 승인하거나 수행하지 않는다.
- 이미 실행 중인 과거 JavaScript를 서버가 소급 수정할 수는 없다. 기존 업데이트 안내/새 페이지 진입으로 새 런타임을 받은 뒤부터 요청 보호가 적용된다. 사용자에게 브라우저 캐시·쿠키 전체 삭제를 요구하지 않는다.
- HTTP 캐시 재사용이 줄어 RSC 네트워크 왕복은 발생하지만 서버 ISR은 유지된다. 지도 상세 데이터의 기존 메모리 캐시를 제거하지 않는다.
- 5분을 넘긴 재접속이나 sessionStorage 차단 환경에서는 위치 복원이 제한된다. 네트워크 단절·새 배포로 인한 필수 문서 재로드 자체를 완전히 금지하지 않는다.
- 복구: 이전 검증 Worker 버전으로 롤백. DB/원본 화장실/로그인 저장소/Cloudflare 캐시 전체 purge 없음.
