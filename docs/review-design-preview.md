# 현장 리뷰 디자인 프리뷰

연결 WBS: [WEB #205](https://github.com/toilet-project/toilet-web/issues/205), [API #105](https://github.com/toilet-project/toilet-api/issues/105), [정책 후속 DOCS #96](https://github.com/toilet-project/docs/issues/96).

## 현재 범위

사용자 의도에 맞게 `https://preview.geupddong.com/`의 **기존 지도·실제 화장실 카드·내 페이지에 리뷰 UI를 연결**했다. 화장실 정보와 기존 계정 기능은 원래 기능을 사용하지만, 리뷰만 React 메모리에서 체험한다. 리뷰 저장 API는 아직 없으며 새로고침·계정 전환 시 초기화한다.

2026-09-11 피드백 후 통합 프리뷰의 비로그인 체험 우회를 제거했다. 이후 사용자 요청에 따라 **중간 위치 확인 모달도 제거**했다. ACTIVE/필수 동의 완료가 확인된 계정이 카드의 리뷰를 누르면 그 버튼을 로딩 상태로 바꾸고 기존 서버 세션 조회와 기기 위치 확인을 병렬로 진행한다. 둘 다 성공한 뒤에만 완성된 작성창을 연다. 위치/정확도/권한/통신 확인 실패 시 카드 버튼을 새로고침으로 바꾸고 짧은 안내를 표시하며, 명시적 재시도는 새 위치를 요청한다. 거리 초과는 창 없이 '150m 이내에서 작성할 수 있어요' 안내만 표시하고 리뷰 버튼은 유지한다. 카드·지도 위치는 바꾸지 않는다. 비로그인 상태면 기존 로그인 안내만 열고 카드 선택만으로 GPS를 요청하지 않는다.

새 리뷰는 화장실 150m 이내·정확도 50m 이하·최근 5분 측정값을 요구한다. 2026-09-11 사용자 요청으로 기존 1분을 5분으로 변경했고, 단일 상수를 최초 검사·세션 검사 완료 후·저장 직전 검사·브라우저 위치 캐시 허용시간에 사용한다. 최초 측정 시각을 검사하므로 캐시 사용이 유효기간을 늘리지 않으며, 캐시가 없으면 새로 측정한다. 저장 시에도 서버 세션과 위치를 병렬 재검사한다. 오류 후 '다시 확인'은 새 측정을 강제하여 부정확한 캐시를 반복하지 않는다. 처음 GPS를 잡는 시간·권한 허용 시간까지 즉시 완료된다고 보장하지 않는다.

지도 기준점/검색 주소는 사용하지 않는다. 앱은 사용자 좌표를 별도 보관하거나 서버에 전송하지 않으며, 계정 전환/취소/화면 종료 뒤 늦게 끝난 검사로 작성창·로그인창을 다시 열지 않는다. 입력을 시작한 뒤 재검사/재시도가 진행되거나 실패해도 작성폼과 입력을 보존하고, 등록만 차단한다. 작성 중 이동·GPS 오차·세션 만료로 저장 재검사가 실패할 가능성은 남는다. 기존 리뷰 수정은 동일 로그인 계정과 최초 작성 7일 기한을 검사하며 재방문을 요구하지 않는다.

이 검사는 **프리뷰의 클라이언트 접근 제한**이며 서버 리뷰 API 검증이나 방문 증명이 아니다. 브라우저 위치 조작을 완전히 막을 수 없다. 실제 저장 API에서 거리·소유권·신선도 등을 별도 검증하기 전 운영 기능을 활성화하지 않는다.

통합 UI는 `SITE_INDEXABLE=false` 빌드에서만 활성화된다. 운영 빌드에는 새 진입 버튼이 없다. `/review-preview`는 오류/기한 시나리오를 위한 기존 격리 실험실로 유지하며 운영에서는 404다. 디자인 검토의 기본 진입점은 별도 실험실이 아니라 **기존 지도 홈**이다.

- 카드 이름 우측: 사이렌 제보 / 평가 행 우측: 기존 말풍선·펜 계열 리뷰.
- 필수: 만족도/청결도 별점 1~5, 화장지 유무. 대기시간 기본 0분, 200자 자유글은 선택.
- 화장지 '있었어요' 선택은 파란 계열, '없었어요' 선택은 빨간 계열로 표시한다. 선택하지 않은 버튼은 중립색이며, 글자·아이콘·`aria-pressed`도 유지해 색상만으로 구분하지 않는다.
- 자유글 입력칸에 초점이 있을 때 키보드로 가시 영역이 축소/이동되면 리뷰 카드 내부만 스크롤해 입력칸을 노출한다. 공간이 되면 '한 줄 더 남겨주세요' 제목도 함께 표시한다. 공통 제보 화면은 수정하지 않고 리뷰에만 연결했으며, 핀치 줌을 방해하지 않는다. 이벤트/관찰자는 닫을 때 해제한다.
- 혼잡도 원활/대기/혼잡 선택 UI와 입력 필드를 제거하고, 항상 보이는 대기시간 바 0~60분/10분 단위로 대체했다. 60분은 '1시간 이상'. 0분도 저장하며 수정 시 기존 시간 복원, 다시 0분 선택도 유지한다.
- 10분마다 눈금/숫자 직접 선택, 가운데 30분 정렬. 내 리뷰 전문은 대기시간을 표시한다. 카드의 기존 혼잡도 자리는 최신 수정된 체험 리뷰의 0분이면 원활/양수면 대기로만 표시한다. 혼잡 판정 임계값이나 정식 집계 규칙을 임의로 확정하지 않는다.
- 상세 카드와 작성창이 같은 별 SVG를 사용한다. 작성 별은 밝은 금색, 정수 `n / 5` 점수를 별 바로 옆 같은 높이에 배치한다. 상단 체험 배너는 없으며 44px 별·버튼과 16px 글 입력을 유지한다. 작성창 높이/위치는 고정하고 내부만 스크롤한다.
- 카드의 리뷰 버튼은 확인 중 회전 아이콘/확인 중 문구와 aria-busy, 실패 시 새로고침 아이콘/재확인 문구를 제공한다. 거리/위치 오류 안내는 리뷰 버튼 바로 위(공간 부족 시 아래) 짙은 녹색 말풍선으로 6초 표시한다. Portal로 카드 스크롤 영역의 잘림을 피하고 스크롤/리사이즈를 따라가며, 별도 창이나 지도 상단 토스트는 열지 않는다. 화면 표시가 끝나도 버튼의 보조 설명은 유지한다. 중복 클릭을 막고 모션 감소 시 회전 없이 문구로 상태를 알린다. 다른 카드 선택/카드 닫기/탭 이동/계정 변경은 진행 중 검사를 무효화한다. 이미 쓰던 리뷰의 저장 재검사는 기존 입력을 유지하고 창 안에서 재시도한다.
- 별/슬라이더/버튼의 기본 회색 터치 하이라이트와 별 축소 효과를 제거했다. 키보드의 `focus-visible` 표시와 선택 상태 색은 유지한다. 실제 iPhone에서 보인 깜빡임이 모두 사라졌는지는 실기기 인수로 별도 확인한다.
- 작성 → 내 리뷰 → 전문 → 수정 / 작성자 정보 지우기. 최초 작성부터 7일 제한.
- 모바일 내 페이지의 내 제보·내 리뷰는 헤더/하단 내비게이션을 유지한 채 가운데 영역에서 연다. URL 이동·목록 모달 없이 공통 기간 필터와 둥근 카드를 사용하고 상세는 카드 안에 펼친다. 별도 뒤로가기 행을 없애고 제목 왼쪽·닫기 X 오른쪽을 같은 행에 배치한다. 닫기는 내 페이지로 돌아가며 하단 탭 이동을 유지한다. 리뷰 수정 창은 기존 모달을 사용하며 닫기/저장 후 현재 목록으로 돌아온다. PC는 기존 목록 창 형식을 유지하면서 같은 기간 필터·카드 상세를 사용한다.
- 두 목록의 기본값은 한국시간 오늘 포함 최근 7일, 최초 작성일 최신순이다. 최근 30일/전체/조절 아이콘의 시작일·종료일 직접 선택을 지원한다. 선택한 종료일까지 포함하며 역순·빈 날짜·미래 날짜는 적용하지 않는다. 제보 상태별 건수도 해당 날짜 범위로 계산한다.
- 최초 10개, 목록 내부 스크롤 끝에 가까워지면 10개씩 추가 표시한다. 자동 감지가 없는 환경을 위해 더 보기 버튼도 유지한다. 필터를 바꾸면 상단/10개로 초기화한다. **현재 제보 API는 전체 배열을 읽으므로 서버 페이지네이션이 아니라 클라이언트 필터·점진 렌더링이다.** 리뷰는 기존 메모리 목록을 사용한다.
- 받은 알림에서 특정 제보로 진입하면 날짜를 전체로 바꾸고 해당 제보까지 표시/펼침/내부 스크롤한다. 일반 진입은 최근 7일을 유지한다. 세션 만료 후 로그인하면 내 제보 내부 목록으로 복귀하고, 다른 계정의 이전 내역은 남기지 않는다.
- 내 리뷰의 휴지통 → 안내 → 최종 확인한 **해당 리뷰 1건만** 작성자 이름을 '익명'으로 표시하고 내 목록에서 제외한다. 일반 리뷰 작성자명이나 계정 닉네임을 일괄 변경하지 않는다. 자유글·선택 값·평가는 유지하며 실제 회원 탈퇴와 구분하고 복구 불가를 확인창에서 설명한다. 수정하기 오른쪽의 휴지통 아이콘은 44px 터치 영역과 접근성 이름을 유지한다. 7일 기한은 기존대로 적용한다.
- 별도 `/review-preview` 실험실에만 가상 위치/로그인/7일 경과/저장 실패 설정을 둔다. 실제 지도 화면에는 모의 로그인이나 위치 우회 옵션이 없다.

## 검증

### 근거리 실기기 확인용 가상 화장실

프리뷰 홈의 `#review-test=<위도>,<경도>` 전용 링크를 열면 브라우저에만 테스트 마커 1개와 카드를 만든다. 좌표는 링크에서만 읽으며 사용자별 주소·좌표는 소스/공개 WBS에 기재하지 않는다. 서버 시설 레코드·검색 목록·집계·SEO 경로에는 추가하지 않고, 음수 예약 ID는 상세 API에 조회하지 않는다. 주변 지도/타일 조회는 기존 지도 기능을 그대로 사용한다.

카드와 마커는 가상 지점임을 표시하고 실제 제보를 차단한다. 로그인·기기 GPS·150m/50m/5분 검사와 리뷰 메모리 저장은 기존 통합 프리뷰와 동일하다. 이 링크는 위치나 인증을 증명/우회하지 않는다. 프래그먼트를 제거하면 마커가 사라지고 변경하면 메모리 리뷰까지 초기화한다. 운영 빌드에서는 유효한 링크라도 아무 시설을 생성하지 않는다.

`tests/review-test-toilet-browser.cjs`는 개인 주소가 아닌 공개 장소 좌표로 마커 1개, 닫기/재선택, 로그인·거리 제한, 링크 추가/제거, 업무 쓰기·가상 ID 요청 0건을 확인한다.

`pnpm lint`, `pnpm typecheck`, `pnpm test`에 더해 `tests/review-preview-browser.cjs`로 격리 프리뷰를, `tests/review-map-integration.cjs`로 기존 지도·단일/목록 카드·내 페이지 통합을 검사한다. 브라우저 실행 시 `PLAYWRIGHT_PACKAGE`는 설치된 Playwright 패키지를 가리키며, `REVIEW_PREVIEW_ORIGIN`은 로컬 시험 주소 또는 `https://preview.geupddong.com`만 허용한다. 통합 시험의 계정은 브라우저 내 가상 데이터이고 업무 쓰기를 차단한다. 로컬 지도 SDK는 모형, 실제 프리뷰의 지도 SDK는 공개 카카오 지도다.

브라우저 검사: 생성/수정/작성자 연결 해제/본문 잔존/7일 경계/150m 실패/정확도 부족/오래된 측정/권한 거부/저장 직전 재검사와 입력 보존/세션 만료/비로그인 GPS 미호출/새로고침 초기화, 폭 320·390·1280의 가로 넘침, 첫 터치 가운데 30분 선택·모든 눈금·창 위치 유지. 추가로 별 SVG 일치·점수 수직 중앙 및 6~12px 간격, 회색 하이라이트 비활성, 기본 0분·30분 저장 후 0분 수정, 150m 안내 한 줄 전체 표시, 재확인 점멸·모션 감소를 검사한다. 리뷰/회원 쓰기 요청은 차단한다. 공개 프리뷰의 기존 Cloudflare `/cdn-cgi/rum` POST는 성능 측정으로 별도 집계한다. Chromium 모바일 에뮬레이션이며 실제 iPhone Safari/Chrome 인수와는 다르다.

대기 UX 회귀에서는 세션/GPS 응답을 모두 보류해 카드 버튼만 로딩으로 바뀌고 모달이 없는지 확인한다. GPS만 완료되어도 작성창을 열지 않고 둘 다 통과한 뒤에만 연다. 카드 경계/지도 기준점/URL 유지, 중복 클릭 방지, 모션 감소, 거리 초과 안내가 리뷰 버튼 근처에 있고 카드 뒤에 가려지지 않는지, 위치 실패의 새로고침/새 측정, 카드 닫은 뒤 늦은 인증 응답 무시를 검사한다. 작성 도중 저장 재확인 실패/재시도에는 기존 별점·자유글을 보존한다. 화장지 파랑/빨강과 선택 상태를 확인한다. 측정한 버튼 상태 표시 시간은 시험 환경의 결과이며 실제 GPS 소요시간 수치가 아니다.

`tests/review-keyboard-browser.cjs`는 320/390/1280px에서 visualViewport 높이/offsetTop을 모의해 입력칸의 카드 내부 노출, 글 보존, 핀치 줌 존중, 닫기/재열기와 이벤트 해제를 검사한다. 실제 iPhone 키보드를 구동한 검사는 아니므로 실기기 인수는 별도로 남긴다. 위치 경계는 1분 초과~5분까지 허용, 5분+1ms 거부, 미래 시각 거부를 검사하고 통합 프리뷰에서 4분 측정값의 최초 작성/저장을 확인한다.

## 받은 알림 통합 (2026-09-11)

- 모바일 하단 알림은 받은 알림 목록을 헤더/하단 내비게이션 사이에서 바로 연다. 내 제보 선택 메뉴와 별도 받은 알림 진입 버튼을 제거했다. 내 제보는 내 페이지에서만 일반 진입한다.
- 기본 최근 7일·최근 30일·전체·직접 날짜를 같은 HistoryFilters로 제공한다. 한국시간 날짜와 최신순을 사용하고 화면에 10개씩 추가한다.
- 기존 알림 API는 20개 단위 서버 페이지 조회이므로 필요한 날짜에 도달할 때까지 다음 페이지를 읽는다. 알 수 없는 전체 건수는 ‘N개 이상’으로 표시한다. 날짜 범위보다 오래된 항목에 도달하면 중지하고, 한 번에 최대 5페이지 후 제어를 반환한다. 긴 검색은 다음 로딩으로 이어지며 조기에 빈 목록/완료라고 표시하지 않는다.
- 알림 읽음/모두 읽음·미읽음 배지·알림에서 해당 제보 상세 연결을 유지한다. 모두 읽음은 기존 API와 동일하게 선택 기간 밖도 포함한다(버튼 설명에 명시). 읽음 요청은 자동 재전송하지 않으며 오류 때 내역은 미읽음으로 남긴다. 조회/필터는 업무 쓰기를 하지 않는다.
- PC는 기존 알림 창을 유지하며 같은 필터·카드·페이지 조회를 사용한다. 모달 초점 가두기는 PC에만 적용하고 모바일에서는 내비게이션을 사용할 수 있다.
- `tests/notification-history.test.mjs`: 페이지 누적/캐시, 날짜 범위, 중복 제거와 읽음 보존, 취소, 잘못된 응답, 5페이지 단위 반환.
- `tests/notification-history-browser.cjs`: 320/390/1280px 합성 알림 45개·3페이지로 7/30/전체/직접 날짜, 10개 추가 표시, 모두 읽음, 오류 재시도, 빈 기간, PC 초점 복귀. `tests/mobile-session-expiry-regression.cjs`: 조회/단건·전체 읽음 401, 계정 분리, 자동 재전송 없음. 실제 업무 쓰기는 모두 차단/가상 응답한다.
