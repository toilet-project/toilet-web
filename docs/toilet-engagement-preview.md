# 화장실 조회수·회원 좋아요·리뷰 혼잡도

WBS: [WEB #343](https://github.com/toilet-project/toilet-web/issues/343), [API #229](https://github.com/toilet-project/toilet-api/issues/229), [ADMIN #144](https://github.com/toilet-project/toilet-admin-api/issues/144).

## 캐시 유지 계약

- 기존 공개 화장실 DTO, 상세 본문 템플릿/지문, R2 key, TTL, 정기 예열, 캐시 무효화 경로는 그대로 둔다.
- 조회수·좋아요는 브라우저의 별도 API로만 조회/변경한다. 서버 렌더링·미리 읽기에서는 집계하지 않는다.
- 원본 `toilet.updated_at`과 `region_revision`을 변경하지 않는다. 좋아요/조회수는 `detailPresentation`에 넣지 않는다.
- 회원별 좋아요 상태와 동적 통계 응답은 `private, no-store`. 개인정보·회원 상태를 R2/언어별 HTML에 넣지 않는다.
- `DETAIL_FRAGMENT_TEMPLATE` 값은 기존 `1d7a654f7177535125538d01`을 유지한다.

## 집계 기준

- 상세 통계 행이 화면에 50% 이상, 전경에서 연속 1초 보인 경우에만 조회를 기록한다.
- 브라우저 탭 세션·화장실별 30분에 1회. 직접 진입/지도/지역별 경로/6개 언어가 시설 ID를 공유한다.
- 익명 UUID와 요청 UUID를 전송하며, 서버에는 목적별 HMAC만 단기 저장한다. 브라우저 저장 실패 시 메모리+서버 중복 방지로 계속 동작한다.
- 같은 요청의 응답이 유실되면 같은 요청키로 다시 확인한다. 개별 중복 방지/요청 영수증은 24시간 뒤 제한된 배치로 정리하고 일별·누적 집계는 남긴다.
- 수집 실패 시 상세 내용은 정상 표시한다. JavaScript 차단/네트워크 손실/식별하지 못한 봇 때문에 실제 사람 방문과 완전히 같지는 않다.
- 좋아요는 활성 회원별 시설 하나당 하나. PUT 등록/DELETE 취소가 멱등적이며 서버에서 인증 버전·계정 상태·약관·출처를 확인한다. 탈퇴/정지 계정은 공개 숫자에서 제외하고 최종 회원 파기 시 FK cascade로 제거한다. 복구용 보관을 선택해 복구한 회원의 기존 좋아요는 복원될 수 있다.
- 혼잡도는 최근 7일 리뷰의 작성시각 기준. 평균 10분 이상이면 5분 단위 내림으로 N분 이상. 평균 10분 미만이며 0분이 과반이면 원활, 나머지 5분 미만/5분 이상. 기간·표본 수를 표시하며 실시간 점유로 안내하지 않는다.

## 배포 경계

- 이번 범위는 프리뷰까지다. 운영 기능은 기본 OFF이며 `TOILET_ENGAGEMENT_ENABLED=true`와 기존 검증된 API 대상 조건이 모두 맞아야 웹 UI가 켜진다.
- API는 `engagement.enabled` 기본 OFF, 목적별 HMAC secret 32자 이상, 허용된 출처에서만 작동한다. 운영 기본 허용 출처에 preview는 포함하지 않는다.
- 프리뷰는 격리 MySQL과 시험 회원을 사용한다. 실제 계정 쿠키/JWT는 시험 서버로 전달하지 않는다. 시험 회원 선택은 한시적인 프리뷰 전용이며 운영 인증에 영향을 주지 않는다.
- 운영 전에 API V36 적용/기능 활성화, 관리자 조회, 웹 활성화 순서와 개인정보 안내의 익명 시설 집계·좋아요 보관 항목을 확인한다. 이번 프리뷰로 운영 정책을 변경한 것으로 취급하지 않는다.

## 검증

2026-10-01 프리뷰 검증 완료. 웹 458개 검사, 격리 MySQL을 포함한 API 검증,
관리자 분석 검증 및 6개 언어/12개 경로의 빌드 간 캐시 재사용 검사가 통과했다.
브라우저에서 회원별 좋아요·취소·새로고침, 30분 조회 중복 방지, 혼잡도 사례,
모바일/PC 표시와 관리자 합계를 확인했다. 실제 OAuth 발급 대신 시험 회원을 사용했다.
운영은 미배포 상태다. 한시적인 프리뷰 URL·유효 시간·검증 범위·CI 증거는 위 WBS에 기록했다.
